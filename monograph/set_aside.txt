Constructing the quoting
operation

The proof in Section 14 uses a program that takes the code of a term and returns
the code of that code. Here’s how to build it.
   Draw the instruction “add one” on a card. Now make a second card describing
the first card’s marks, rather than carrying out the addition. The count has not risen:
you have described an instruction. Describe the second card in turn and you have
a description of a description. Quoting does that second job mechanically. In the
language below, take the variable of index 0. Its code is a tree with three lambda
nodes, then an application of variable 2 to the numeral for 0. Quoting that code
builds a description of those three lambdas and that application; it does not look up
variable 0 or execute the term it describes.
   Nothing in the operation lets a program inspect itself by magic: its input is an
ordinary tree encoded as a closed lambda term.
   The construction follows Forster and Smolka (2017), whose construction for L
has the same three syntax builders on Scott-encoded children, an auxiliary procedure
for numerals, and a quote procedure Q with the same specification, defined by the
same recursion on codes; the self-application that uses Q in Section 14 is their
fixed-point lemma, after Barendregt’s (1984) proof for the full lambda calculus.
What follows is my rebuilding of it, with the reductions written out.

sequence of the weak call-by-value steps ending in the value Y.
   Scott numerals are the following closed values:

               1.2 Recursion without running under a lambda

               The quoting procedure will have to call itself on the smaller pieces of a description.
               There is a catch: this language works out an argument before handing it to a
               function. Hand over the recursive calculation itself and it starts calculating at once,
               before the receiving function has decided whether it needs it. That can send you
               straight back into the same calculation forever.
                   Instead, hand over a recipe waiting for an ingredient. In this language a lambda
               is such a recipe, and it counts as a finished value even though its body has not run.
               The receiving function can keep the recipe and call it when it reaches a smaller
               piece. In the expression below, the little recipe λa.x x f a is the part doing that job.
               The letter a names the argument it is waiting for; f names the work to do once the
               recipe and the current input have been handed over.

                             W = λx.λ f .λv. f (λa.x x f a) v,    rec( F ) = λv.W W F v.
               When F and u are closed values, beta reduction gives

                            rec( F ) u −→ W W F u −→∗ F (λa.W W F a) u = F (rec( F )) u.

1.3 Quoting numerals
Let Ej = ⌜#j⌝ for j = 0, 1, 2, and let Z = ⌜0⌝, obtained directly from the finite
syntax of 0 = λλ.1. Write mklamk ( X ) for k nested applications of the syntax builder
mklam to X; it is an abbreviation for constructing k lambda nodes, and the language
gains no new operation from it.
   Define

        FN = λr.λn. n Z (λk.mklam2 (mkapp E0 (r k))),          Q N = rec( FN ).
Follow the two branches. Zero chooses the already built description Z. A number
one larger than n chooses the other branch and hands it the predecessor n. That
branch first asks the same procedure to describe the predecessor. Then it puts the
description inside an application of variable zero and wraps two lambdas around it.
Those are precisely the marks in the numeral for n + 1.
   Zero therefore works. If the procedure describes n correctly, the wrapping just
described makes it describe n + 1 correctly. Starting at zero and taking one more
step proves the claim for every natural number. Every call on a positive number asks
about a smaller one, so it reaches zero and finishes. In the notation for termination
and returned value, the result is Q N n ⇓ ⌜n⌝.
   Do the smallest case by hand. Call the successor case G. Then Q N 1 steps to
FN Q N 1 and on to 1 Z G; the numeral hands its predecessor 0 to G, the recursive
call Q N 0 comes back as Z, and the builders return mklam(mklam(mkapp E0 Z )).
That is the code of λλ.(#0 0), which is 1.


1.4 Quoting terms

For a proposed recursive call r, define three handlers:
                 HV = λn.mklam3 (mkapp E2 ( Q N n)),
              H A (r ) = λp.λq.mklam3 (mkapp (mkapp E1 (r p)) (r q)),
              HL (r ) = λp.mklam3 (mkapp E0 (r p)).
Now set
               FQ = λr.λt.t HV ( H A (r )) ( HL (r )),    Q = rec( FQ ).

The handlers are lambdas and so are values. The Scott code of the input chooses one
of them and hands it the encoded children. Start at the leaves and build outward.

               At each node the handler builds the syntax of that node’s encoding: Q ⌜t⌝ ⇓ ⌜⌜t⌝⌝.
               There are three kinds of node to consider:
                • For t = #n, the first handler constructs three lambda nodes over an application
                  of variable 2 to the quoted numeral. That is the syntax of λλλ.(#2 n), the code
                  of #n.
                • For t = p q, quote the two children first. The second handler constructs three
                  lambdas over variable 1 applied to those two codes. That is the syntax of the
                  application code.
                • For t = λp, the last handler constructs three lambdas over variable 0 applied to
                  the quoted child code. That is the syntax of the abstraction code.
                  Each recursive call works on a proper child of the finite input tree, or on a
               smaller numeral. No chain of calls can keep descending through a finite tree or
               decreasing a natural number forever. Each builder takes finitely many beta steps, so
               the construction finishes and returns the code just described.
                  The mkapp used in Section 14 is this builder. With Q and that builder written
               out, every piece of the self-referential term there is on the page.

From “A record and a toll”

Take an ordinary computing machine and put a lamp and tally beside it. Let
computing run as before, leaving both alone. A separate mark leaves the computing
state fixed, adds one to the tally and turns the lamp on when its named event holds.
Forget the lamp and tally and the old computation is still there, step for step. Below
I build that box, compare different ways to implement it, and ask exactly which
differences its questions require. The old machine may already have prices or a
reading of its own; this construction supplies the new lamp and its zero/one account.
With effective rules an ordinary computer can store all three parts.

What the next move could tell us
Put two boxes beside each other and read everything the task lets you read. Suppose
the answers agree. That is not yet enough to put the boxes in the same pile. Press
the same button on each. Perhaps one lamp now comes on and the other stays dark.
The difference mattered, even though the first reading missed it.
    Keep two states together only when every permitted finite continuation gives the
same required answer. Include doing nothing: the current answer counts too. This
tells us which differences the task can afford to forget.


Theorem 2.1 (Keep what a later question can separate). For a fixed deterministic
machine, permitted instructions and required observation, equality of observations
after every finite continuation is the unique coarsest equivalence that preserves
the current observation and is stable under every instruction. A deterministic
implementation preserving those steps and answers cannot identify two states
separated by such a continuation.

Proof. Agreement with oneself, reversal of an agreement, and joining two agree-
ments all hold one continuation at a time, so this is an equivalence. Doing nothing
checks the current observation. To check stability after a move, put that move in
front of each continuation. If two states were already grouped by any observation-
preserving, stable relation, apply its stability once for every move in a continuation,

               The picture, the lamp and the tally
               Take an ordinary computing box. Put a lamp beside it and a tally beneath it. A
               computing button moves the box by its old rule, costs zero, and leaves the lamp and
               tally alone. A mark button leaves the box where it is, adds one to the tally, and turns
               the lamp on if its named event holds there. Once on, the lamp stays on. Start with
               the lamp down and the tally at zero.
                   Those instructions tell us what to do without telling us how to build the box. One
               builder may keep every button press on a tape. Another may keep an extra turn
               counter. I require each builder to show me the same three things: the computing
               picture, the lamp and the exact tally. Its computing moves must follow the base rule
               through that picture. Its marks must leave the picture fixed and latch exactly the
               named event. Its prices are zero for computing and one for marking; its reading
               obeys the toll and permanence; its tally increases by exactly the charge on every
               move.


               Theorem 2.2 (Every such box has the same three-part description). Fix those
               base rules, mark events and accounting requirements. Every implementation has
               exactly one map to the product of base state, Boolean reading and natural tally
               that preserves the three readings. That map preserves every instruction and every
               finite run. From a start with lamp down and tally zero, it maps the reachable
               implementation states onto all reachable states of the product lift with the matching
               base start.

               Proof. Read the picture, lamp and tally, and write them down in that order. There
               is no other choice for a map required to preserve those three readings. Press a
               computing button. The picture follows the base rule. The lamp stays put by the toll
               and permanence, and the tally stays put because the charge is zero. Press a mark
               instead. The picture stays put, the lamp takes its old value or the event’s yes, and

the tally rises by one. These are exactly the two rules of the product lift. Repeat for
every move in a finite run.
   The clean starts agree in all three readings. Any reachable product state has some
finite list of buttons reaching it. Press that same list on the implementation. The
step argument makes its three readings the desired product state. Every reachable
product state therefore has a reachable implementation state above it.
    Here are the three stages. First write a list of buttons. Then run it on the builder’s
box. Then read the picture, lamp and tally. You get the same result as running the
list directly on the three-part description. Written as arrows, after we have done it:

         button lists −→ implementation states −→ picture, lamp, tally.
    The first arrow has only one possible meaning once the start and buttons are
fixed. The empty list gives the start; appending a button takes one more step. This
is the free history construction. The second arrow can forget history. Its direction
matters.
    Turn a box halfway around with a free button. Turn it again. It is back where it
started, with the same lamp and tally. Now give another builder’s box a counter that
goes up on every turn, without charging for it. After two turns its counter is two
larger. It meets all the requirements above: the extra counter is separate from the
tally of charges.


Proposition 2.3 (Forgetting the turn count goes one way). Even on reachable states,
the three-part lift need not have a step-preserving map into every implementation
satisfying its contract.

Proof. In this example two turns return every product state to itself. A map pre-
serving turns would have to send it to an implementation state that also returns
after two turns. No such state exists there: its extra counter has increased by two.
Forgetting that counter works in the other direction and preserves both turning and
marking.
    There is an exact way to tell when the reverse map would work. Whenever two
button lists reach the same source state, they must also reach the same target state.
Otherwise the map would have to send that one source to two targets. Supply one
access list reaching each source state, and this condition is sufficient: run its access
list on the target. Any other list reaching that source gives the same target by the
condition. The empty list preserves the start, appending a button preserves a step,
and reachability leaves no other possible map. The turn counter fails exactly this
test: the empty list and two turns agree in the source and disagree in the target.

               Theorem 2.4 (The smallest description that answers these questions). Under the
               preceding contract, two implementation states give the same three readings after
               every common finite continuation exactly when their current three readings agree.
               If every two distinct reachable implementation states can be separated by such a
               continuation, projection is a bijection onto the reachable product states. It preserves
               starts and steps and is the unique start- and step-preserving map there.

               Proof. If the current readings differ, read them now. If they agree, the two product
               states are equal. Equal states obeying the same rule give equal next states; repeat
               for every move. Projection preserves those moves, so the implementation’s readings
               agree throughout too.
                   Now require every distinct reachable pair to be separable. Two states projecting
               to the same triple could never be separated, so they must be one state. Projection
               is therefore one-to-one; the previous theorem makes it onto the reachable product
               states. Any start- and step-preserving map is fixed on a reachable state by a list
               reaching it: map the start, then follow the list. It must agree with projection there.
                   The same reasoning explains uniqueness more generally. Take two reachable
               machines with the same answers to every button list from their starts, and suppose
               each keeps no two states that all future answers fail to separate. Supply an access
               list for each state of the first. Run that list on the second. If two lists reach the same
               first state, append any continuation: their answers agree on the first machine, hence
               on the second. Separation in the second makes their endpoints equal. The map is
               well-defined and preserves steps and outputs. Reachability makes it onto; separation
               in the first makes it one-to-one. Following an access list forces uniqueness.

What can choose the question?
Take a dial with two faces and one button. Each press turns it to the other face.
For this question, supply no starting face, no lamp and no names with an outside
meaning. Draw its two arrows. Now exchange the names on the two faces. The
arrows describe exactly the same machine.
   Suppose those arrows alone are meant to tell us which face deserves yes. A rule
that does not depend on our choice of names must give the exchanged face the
same reading. So both faces get the same answer. A nonconstant reading cannot be
selected that way. Give one face a role, such as the loaded start, a completed job or
a passed check, and I have supplied more to work with. The role has to be stated
and defended. Renaming the arrows did not supply it.
   The argument is two lines: the exchange takes the first face to the second;
respecting that exchange makes their readings equal. Those are all the faces. It
does not make every machine’s reading constant. It rules out a nonconstant reading
selected from the transition structure alone on every machine.
   That fixes what the uniqueness claim can say. The box, lamp and tally have a
unique observable realization under the contract already proved. The arrows by
themselves do not choose that contract. Adding the word “intrinsic” cannot do the
choosing for us.

switch to the lamp. Start with the lamp dark in both boxes, and put the hidden
switch down in one, up in the other.

From “Why the toll isn’t arbitrary”

There is also a limited statement about how long a noisy record lasts, using a
different quantity: total entropy production during relaxation. Take a device with
no outside hand: a random process hopping among finitely many states at rates that
never change, with a reverse for every hop and local detailed balance, able to get
from any state to any other. Require at least one up-state and one down-state. Left
to run, it settles into a long-run spread π. Measure each up or down stretch from
its entrance, with entrances sampled in the stationary process, and call the mean
lengths Tup and Tdown . Start the device in a known no-state s. The total entropy it
produces over relaxation is at least ln(1 + Tup /Tdown ), in units of k B .
    First compare the starting spread with the spread the device settles into. A state
that is common at the start but rare in the settled spread is a large mismatch. For
each state, take the ratio of those two chances, take its natural logarithm, and
average using the starting chances. With p the starting spread, that number is

It is called relative entropy. Here every π ( x ) is positive, so the ratios are available.
The number is nonnegative: apply ln y ≤ y − 1 to π ( x )/p( x ), multiply by p( x ), and
add. The right side is at most zero, since the included π chances total at most one
and the p chances total exactly one. Negating that comparison gives D ( p∥π ) ≥ 0.
    For a known start s, all the starting chance is at s. There is only one term:
D = ln(1/π (s)) = − ln π (s). A state with settled chance one tenth therefore starts
with mismatch ln 10. Since s is a no-state, its settled chance cannot exceed the total
chance of all no-states. Its mismatch is at least − ln π (no).
    The physical step in the argument is the fixed-rate entropy-production split of
Massimiliano Esposito and Christian Van den Broeck (2010). In that setting the total
entropy produced is at least the decrease in this relative entropy. Once the spread
has settled to π, the relative entropy left is zero. So the initial mismatch supplies
the lower bound for the whole relaxation.

The two chances add to one. If the ratio on the right is r, the no-share is 1/(1 + r ),

    For a large up-to-down ratio, doubling that ratio raises this lower bound by about
k B ln 2. Making both stretches longer by the same factor leaves it unchanged. Across
a family of devices whose ratio tends to infinity, the bound diverges; no single
finite irreducible device in this class keeps its flag up forever. This is a relaxation
bound, not a heat charge on each flip. It uses neither a thermodynamic reverse-path
construction nor time-symmetric control, so it does not identify the quantities in
those other results. It also leaves the known-input case of the deterministic entropy-
loss bound where it was: this noisy evolution and its total entropy production are a
different question. The entropy is added up over one whole relaxation, from the
known no-state s until the device has settled, and local detailed balance is what
ties it to heat exchanged with the reservoirs. Total entropy production includes the
change in the device’s entropy too; it is not heat alone. It also isn’t the permanence
of the finite-state theorems on a noisy device: on this device the flag comes back
down, and Tup and Tdown are average stretches.
    The core of it for a chain that ticks, worked out, runs as follows in the case where
the long-run spread π gives every state a positive chance and satisfies detailed
balance: in the long run as much weight flows from x to y in one step as from y
to x, π ( x ) P( x, y) = π (y) P(y, x ), where P( x, y) is the chance of stepping from x
to y. Count the entropy produced in one step as the change in the device’s own
entropy plus what goes out to the surroundings, which for a hop from x to y is
ln( P( x, y)/P(y, x )). Detailed balance turns that ratio into π (y)/π ( x ), and the sum
collapses: the entropy produced in one step is exactly the drop in relative entropy to
π. It’s never negative, because a step that leaves π where it is can’t make any other
spread harder to tell from π (that’s the data-processing inequality, a standard fact of
information theory). Add the steps up and the sum telescopes. A known start s has
relative entropy − ln π (s), so the entropy produced in the first T steps is − ln π (s)
minus the relative entropy left at step T: it never exceeds − ln π (s), and it reaches it
in the limit exactly when that remainder goes to zero. Next, − ln π (s) ≥ − ln π (no),

                  Settling comes first. A chain doesn’t have to settle. It can get stuck in a corner, or
               cycle round forever. What rules that out here is a condition named for Wolfgang
               Doeblin, a German-born French mathematician, son of the novelist Alfred Döblin,
               who took his doctorate at the Sorbonne in 1938 for work on chains like this one and
               died in June 1940, at twenty-five. In words: from wherever the device is, its next
               step lands on each state with at least some fixed fraction δ of that state’s long-run
               chance. No state is ever out of reach in one step, and none is favoured so heavily
               that the others starve. Under that condition each step shrinks the distance between
               where the device is and where it’s going by the factor 1 − δ (the distance here is the
               total of the differences in chance, state by state). To see why, split each step in two:
               with chance δ, forget where the device was and draw a fresh state from π; otherwise,
               move by whatever is left over, and the condition is exactly what makes the leftover
               a genuine set of chances. The fresh draw puts the device’s spread and π in the same
               place, so only the other share, 1 − δ, can keep them apart, and no step pushes two
               spreads further apart than they were. So the distance dies off geometrically and the
               spread converges to π at every state. The payoff for the bound is that the entropy
               produced from the known start stays under − ln π (s), and it also gets there: after T
               steps it falls short by at most (4/πmin )(1 − δ)2T , where πmin is the smallest long-run

chance of any state. The shortfall is the relative entropy left, and ln y ≤ y − 1 once

    For rates satisfying detailed balance with π, the same equality holds when the
device hops at random moments, with no clock ticking. Write out how fast the
relative entropy to π changes and pair each hop with its reverse. Detailed balance
makes each pair’s share minus (the flow one way minus the flow back) times the
logarithm of their ratio, and that is exactly the pair’s share of the rate entropy is
produced; a difference times the logarithm of the same ratio is never negative. So at
every instant the relative entropy falls at exactly the rate entropy is being produced,
and that rate is never negative; add the rate up between two times and you get
exactly the drop in relative entropy between them. For settling, Doeblin’s condition
becomes a condition on rates: the rate of hopping from any state x to any state y
is at least c times π (y), for some fixed c > 0. Split the rates in two again: a part
that, at rate c, forgets where the device was and redraws it from π, and the rest,
which still satisfies detailed balance. The production rate adds over the two parts,
because with detailed balance it’s the rates times quantities that don’t depend on
the rates. The rest produces nothing negative, and the redraw part alone produces
at least c times the relative entropy still left. So relative entropy falls at least as fast
as e−ct . One wrinkle needs its own line. A known start puts all its weight on one
state and none anywhere else, and the logarithms in the relative entropy go bad at
zero. The relative entropy is still continuous at the starting instant, because each of
its terms has the form u ln(u/π ), and u ln u goes to zero as u does. So adding up
the production from the start out to infinity gives exactly − ln π (s).
    I should say what Doeblin’s condition costs. It asks for every hop to be possible
directly, in one step or at a positive rate. A device whose states reach each other
only through other states can still settle, and the standard theory of these chains
says when: always, for a device that hops at random moments and can get from any
state to any other; and for a chain that ticks, as long as it also doesn’t march round a
cycle. Those devices meet the condition for some fixed stretch of time or number of
steps instead of one, and the same argument runs on blocks of that length, because
the relative entropy never goes up in between.
    Then come the stretches. The bound used the fact that the long-run chances of
up and down stand in the ratio of the mean stretch lengths, and I took the mean
length of a stretch with the flag up to be the long-run weight of the up-states divided
by the flow into them. For a chain that ticks, that’s right for the following reason.
Start each stretch the way the flow starts them, count the steps until the chain leaves
the up-states, and the average is exactly π (up) over the flow. Look at the long-run

Definition 4.1 (Decision tree). A decision tree is a leaf, or a branch with two subtrees.
Its depth is 0 for a leaf and one more than the deeper subtree for a branch; its leaf
count L( T ) is 1 for a leaf and the sum of the two counts for a branch. Nothing is
written on a tree: no question, no answer, no candidate.



Lemma 4.1 (A tree is no wider than two to its depth). For every decision tree T,
L( T ) ≤ 2depth(T ) , and so ⌈log2 L( T )⌉ ≤ depth( T ).

tips reach the tree’s greatest depth. This only adds leaves. At depth d the filled-out
tree has 2d tips, so the original tree has at most that many leaves. For depth zero
there is just the root, which is one leaf.

will do, ⌈log2 L( T )⌉, cannot be greater than d.

2n − 1 give n index bits for the same cost of three.

doesn’t. Two information theorists, Rudolf Ahlswede and Gunter Dueck (1989),
noticed that asking “is it this one?” is a different job from asking “which one is it?”
If each receiver only wants to know whether the message is theirs, a noisy channel
used n times can serve a number of receivers that grows like two raised to two to
the nC, with C the channel’s capacity, where naming the message only gets you
two to the nC. The task is called identification, and on its face it says checking
can be exponentially cheaper than naming. But their tests are allowed to say yes
wrongly once in a while. Make the yes sound, a test that never says yes to the wrong
message, which is the only kind of check this book lets raise a record, and the double
exponential collapses. The argument is two lines of pigeonhole. Each receiver’s test,
to be any use, says yes on some output its own message can produce, and soundness
means no other message can produce that output; so those outputs are all different,
one per receiver, and there can’t be more receivers than outputs, |Y |n for an output
alphabet Y. That bound is single exponential, the same order as naming. So for a
check that never lies, the card count is the right scale after all, and the cheap trick
needs a check that can be fooled.

5.1 Bases from outside, and a relation I have to be honest about

The theorem is stated for any base, so let me put it on three models of computation
that other people built: a small Turing machine (any program); a register machine
of the kind the computer scientists Stephen Cook (of the certificates) and Robert
Reckhow described in 1973, with unit-cost indirect addressing (any program); and
a lambda calculus (call-by-value, meaning an argument is worked out before it’s
plugged in, and made deterministic by letting a term with no step left to take step

is a register machine plus a cup, and so is a lambda calculus.

6.1 How much gets destroyed, on average

The halving price is a worst case, because it prices the largest landing pile a move
can have. The next question is the average one: if I don’t know which state the
machine was in, cups and all, but I have some spread of chances over the states,
how much do I lose, on average, about which state it was, once I know where it
landed? Shannon’s conditional entropy measures exactly that (Section 3 built the

Theorem 6.1 (The halving price in bits bounds the average loss). Take any spread

information loss is at most its cost in bits times the total weight, even when the
spread’s own entropy is infinite. For a probability distribution, the total weight is

the uncertainty is greatest when those possibilities have equal shares, and is then
at most log2 N bits. Multiply by w to put this pile back into the whole spread. Its
contribution is at most w log2 N. A pile with zero weight contributes nothing.
   Add the contributions. The pile weights add to the original total weight, so
the same log2 N multiplies that total. Under the halving price, N = 2cost , whose
base-two logarithm is exactly the cost.

   Bennett again, the one from Part I’s counting of states and the demon, wrote a

to find where it parts from mine, because if I couldn’t find that place I’d just be
renaming his idea. And it’s one word: plausibly. Depth is the amount of work a
thing was plausibly made with. Bennett says straight out that you can’t know how a
message actually came to be; for all you know it came from flipping coins. Depth is
read off the finished thing, the way a fossil’s age is read off the fossil.
   Bring the two computers back. The sorted list in the first one has some depth.
The identical list in the second has exactly the same depth, because depth looks at
the list and nothing else. A photocopy of a deep thing is just as deep. Depth tells
you what work a plausible way of making the thing would take. It’s not a record
that this machine did it, and it’s not a receipt for what doing it cost.
   So Bennett’s standing right next to the line, on the other side of it, and as far as I
can tell he got his own question right. He asked how much work a thing embodies.
I’m asking who has the right to lean on it and what they paid to get there. His
answer lives in the object. Mine, if I’ve got one, has to live in the machine.

This section has definitions, two toys, a theorem about independence, a survey, and

   The definitions are the ones above, plus “unique pointer among rivals”: the event
proliferates and none of a listed set of rival events does. Uniqueness is relative
to the list, necessarily, since any event that holds on exactly the same states as a
proliferating event proliferates whenever it does: the same fact under another name,
so someone has to say which names count as rivals. And the first criterion is stated
as a schema: for every ecosystem in some class, its metered event is the unique
pointer among its rivals. The class and the rivals are inputs. Nothing about them is
proved. A second set of definitions, after this one, tightens “proliferates” to “copied

and no rival in the list does. Given a class C of ecosystems, and for each member a
designated metered event and a list of rivals, the pointer criterion holds for C when

    Put one yes/no card in front of each of two readers. If the cards can be set
separately, all four arrangements are allowed: no/no, no/yes, yes/no and yes/yes.
Ask each reader to recover one shared event using only their own card. Suppose
that event is false at no/no and true at yes/yes. At no/yes, the first reader sees
exactly what they saw in the false case, while the second sees exactly what they saw
in the true case. Their answers conflict. That mixed arrangement is exactly what the
independence condition hands the proof.

reachable arrangements each reader can report the shared bit correctly. Separate
cards are things that could carry a copy; what makes them copies is that the
arrangements you actually reach have the two agreeing. The theorem below is
about recovering the event exactly on all arrangements, the mixed ones included,
which the copying never leaves behind.

11.1 The calibration is a unit conversion

Multiply the counter by an energy per unit of cost that you choose, and you get
a theorem: a state with one unit, at the scale kT ln 2 per unit, carries kT ln 2 of
energy, for every k and T. Read that for exactly what it is: a unit conversion, true by
definition, with the scale as an unforced input. Nothing in it picks the scale. The
theorem would be just as true with the scale set to a dollar a unit. What would
connect units of cost to joules is the premise in Section 3, Landauer’s principle,
which is a physical premise. And even as a scale, k B T ln 2 a unit is the floor for one
particular squeeze, a halving. Corollary 3.13’s floor for a flip that brings k states in
beside m already reading yes, starting from the even spread on those m + k states,

                                    +k k B T ln 2, and for one newcomer among many
yes-states that’s far below a halving, about 1.4 k B T/m. Price every unit at k B T ln 2
and you can overstate the floor of a single narrow flip by a factor that grows with m.

between a count and heat? It has a newer chapter, and it makes the point sharper
than I can. The k B in k B T ln 2 turns a temperature into an energy, and for most
of its history it was a measured number, with error bars, pinned down by careful
experiments. Since 20 May 2019 it isn’t. That day the international system of units
was redefined so that Boltzmann’s constant is exactly 1.380649 × 10−23 joules per
kelvin, by definition, and the kelvin is whatever makes that true. So the conversion
from temperature to energy has been a convention since then, in the strictest sense:
its numerical value in those units is fixed. Realising the kelvin in a laboratory still
requires measurements, with uncertainty. What’s still physics is everything around
it, whether wiping a bit at a temperature really sheds that much heat, which is what
the Lyon bead was measuring. The calibration theorem is the same kind of move as
that redefinition. It fixes a conversion, and the physics, if there is any, is somewhere
else.

Methodology note

Everything this book claims as its own stands or falls on the arguments written in
it; what it borrows is cited to the people who proved it, and the physics enters as a
named premise. If a proof on the page is wrong, the result is wrong, and nothing
else I could tell you would rescue it.

claimed something for every run, the argument has to explain why the next step

BUILD THE BOX, THEN FORGET WHAT THE TASK DOES NOT ASK FOR

The smallest machine above an ordinary computing box has a lamp beside it
and a tally under it. Computing buttons follow the old rule, cost nothing,
and leave the lamp and tally alone. A mark leaves the computing picture
alone, adds one to the tally, and turns the lamp on if its named event holds.
Once on, it stays on. Begin with the lamp down and the tally at zero.

Run only computing buttons and the old machine runs exactly as before.
Forget the lamp and tally afterward and you recover its computation.
The larger description contains it. An event that holds somewhere gives
a visible difference between before and after marking even when the
computing picture stays the same. An ordinary computer can store the
picture, lamp and tally when their rules are effectively given.

Now let two builders implement those instructions differently. One keeps
every button press on a tape. The other uses a few extra counters. Ask
each for the computing picture, lamp and exact tally. Require computing
to follow the base rule, marks to latch exactly the named event without
changing the picture, and each move to add its zero-or-one charge to the
tally. The reading must obey the toll and permanence.

Read those three things from either implementation. After a computing
move, the picture follows the old rule; the free move cannot change the
permanent lamp; adding zero leaves the tally alone. After a mark, the
picture stays put, the lamp latches the event and the tally rises by one.
Those are precisely the simple box’s rules. Repeat this for every button
in a list and the readings agree for the whole run. Any list reaching a
state of the simple box reaches an implementation state with those same
readings. Starting together gives all the same reachable triples.

That makes three stages: write a button list, run it on the builder’s

box, then read the picture, lamp and tally. The last step forgets whatever
extra history the builder kept. There is only one way to do it while
preserving those three readings: report their actual values.

Try running that last step backward. Turn the simple box halfway around,
then turn it again. The picture is back, and the lamp and tally never
changed. Give the other box a separate counter that counts free turns.
Its counter is now two larger. Which counter value should the simple
box’s one state turn into? Preserving the turns would require both.
There is no such map. Forgetting the extra counter works; recovering it
from the three readings does not.

To see what has to be kept, give two states the same future button list.
If a required answer differs, those states cannot share one full state
in a faithful implementation. That one state would have to give two
answers to the same continuation. Include the empty list: reading now
counts as a test. Group states only when every such test agrees. Once
grouped, pressing a common button keeps them grouped, because that button
can be put in front of every remaining test. Every grouping that preserves
answers and steps must respect these tests. This is the coarsest one.

For the picture, lamp and tally, equal current readings already give
identical future readings: their next values follow exactly the rules
above. Different triples are distinguished by reading them now. Remove
states that differ only in history these questions can never reveal,
and every reachable triple has exactly one remaining state. Any two
implementations with no such redundancy differ only in the names of
those states. A button list reaching a state fixes its partner in the
other implementation, so even that renaming is forced.

The questions do work here. Ask for the extra turn count and it has to
survive too. Stop asking for the tally and repeated failed marks can
become indistinguishable. If no mark event ever holds, a clean run never
reaches a lamp-up state. The minimum concerns what can be reached and
what the chosen questions can distinguish. It does not select the event.
I develop this familiar idea from minimal automata for
the actual lift, with the observations and accounting kept explicit.

WHAT A FREE MOVE CAN CHANGE

Slide a tile to the right without paying. Ask whether it is in the place
it just reached. The answer was no and is now yes. If the toll charged
every question, that slide could not be free. Do this with any changed
full state: ask whether it is the destination. Where states can be tested
for equality, charging every Boolean question would freeze every free
move. The definition has to name the reading its toll belongs to.

Now keep that reading permanent. A free move cannot raise it, because a
raise costs at least one. It cannot lower it, because a yes stays yes.
It must leave it alone. That explains the reading part of the horizontal
rule. The window adds another requirement: the next picture comes from
the present picture and the button pressed. Permanence by itself does
not choose a picture or make a paid move leave that picture alone.

There are two ways to state the same reading requirement for a sliced
machine. Leave it alone on horizontal moves and never lower it on vertical
moves, and it is permanent through all moves. Start instead with permanence,
the toll and free horizontal moves, and the two sentences above force
horizontal preservation. Neither route has to assume its own conclusion.

Put price cards zero, one and two beside a button. If pressing it can raise
the lamp from some state, zero fails there. One works. Two works too, but
one is the least. If the button never raises the lamp from any state,
zero works. Give each button its least card and you have the least valid
schedule, one instruction at a time. Any other least schedule must have

# Part 5, Item 5.1, round 1 freeze: RFC 9162 Merkle proofs

Date: 2026-10-01

## Actual specification

Authoritative source: IETF RFC 9162, “Certificate Transparency Version 2.0,”
December 2021, <https://www.rfc-editor.org/rfc/rfc9162.html>.

- RFC 9162 Section 2.1.1 defines the Merkle Tree Hash, including distinct
  `0x00` leaf and `0x01` internal-node prefixes.
- RFC 9162 Section 2.1.3.2 defines the iterative inclusion verifier using
  `fn`, `sn`, least-significant-bit tests, paired right shifts, and final root
  comparison.
- RFC 9162 Section 2.1.4.2 defines the iterative consistency verifier using
  `fn`, `sn`, `fr`, `sr`, the power-of-two special case, paired shifts, and
  comparison against both tree heads.

Interpretation calls: the RFC selects a registered hash algorithm as a log
parameter. The Coq verifier therefore accepts a `HashAlgorithm` record. It
models the domain-separated calls and equality check but does not replace a
cryptographic reduction for any registered hash. Entries and digests remain
typed rather than being silently identified with VM values.

# Part 3, Item 3.1, Round 2 freeze: dynamic evaluator and s-m-n

Date: 2026-10-01

## Existing definitions retained

- guest syntax and execution: `GInstr`, `g_program`, `g_run`, `g_beh`;
- numeric code: `guest_program_code p = program_to_nat (g_program p)`;
- behavioral equivalence: `g_equiv`;
- transformer representability and the exact fixed-point target:
  `g_represents_transformer` and `vm_guest_recursion_theorem`.

The original fixed-point statement is not weakened.

## New exact definitions

`g_reify_instruction` is a partial inverse from the full VM instruction type
to the twelve-instruction guest fragment. `g_decode_program` traverses a
decoded full VM program and fails if any instruction is outside the fragment.

`g_eval fuel code input` decodes `code` and, on success, returns the exact
`g_run fuel` result from `g_input input`. The evaluator is a verified
fuel-bounded dispatch function; it is not called an opcode unless a guest
program is proved able to invoke it.

`g_specialize p x` prefixes a load of `x` into guest register zero and
relocates `p` by one instruction.

## Frozen statements

1. `g_decode_program (guest_program_code p) = Some p`.
2. `g_eval fuel (guest_program_code p) x = Some (g_run fuel p (g_input x))`.
3. The decoded evaluation agrees with the actual VM execution theorem
   `g_run_is_run_vm_u`.
4. s-m-n specialization:

```coq
forall p x y g mu,
  g_beh (g_specialize p x) y g mu <-> g_beh p x g mu.
```

5. Re-test the unchanged `vm_guest_recursion_theorem` using the evaluator and
   specialization result.

## Predicted outcomes

- decoder and dynamic fuel-bounded evaluator: PROVED;
- semantic s-m-n specialization: PROVED;
- unchanged guest recursion theorem: predicted BLOCKED unless the numeric
  code constructor `fun z => guest_program_code (g_specialize ... z)` is
  itself represented by a guest program. A Coq-level constructor alone does
  not discharge that internal representability obligation.

## Success

All four construction theorems close and the original recursion theorem also
closes from an internally executed code constructor. Host-side decoding alone
does not count as closing the fixed point.

## Failure

The evaluator or specialization theorem fails, or the fixed-point proof still
requires an unproved guest program computing its own specialization code. If
the latter occurs, the round records the exact residual term and three genuine
attempts rather than relabeling the host evaluator as an opcode.

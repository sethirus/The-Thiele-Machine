# Part 3, Item 3.1, Round 1 results

| Frozen statement | Outcome |
|---|---|
| vm_guest_recursion_theorem | BLOCKED |
| vm_guest_rice | PROVED |

The guest execution and Rice wrappers, plus a concrete representable identity
transformer, are closed under the global context. No closed proof or
counterexample of `vm_guest_recursion_theorem` was obtained.

The exact blocker is dynamic evaluation. Existing actual execution preloads
the guest program structurally into host state. It does not establish a guest
operation that decodes a number produced at runtime and executes that decoded
guest program. The numeric encoding round trip and the fixed host interpreter
do not by themselves provide the s-m-n construction needed for the frozen
fixed-point statement.

The Rice theorem is independent of the blocked recursion theorem: it is
proved by the concrete `rice_prog` reduction from complement-MM2 halting, not
derived from `vm_guest_recursion_theorem`. For well-formed guests, the
execution relation is tied to actual VM execution by
`vm_guest_execution_is_actual`.

## Three recursion-theorem strategies

1. Fixed host interpreter. `self_interpreter_correct` and
   `g_run_is_run_vm_u` were inspected as the execution route. They take `p`
   structurally when constructing the starting host state; no runtime guest
   result becomes the next interpreted program.
2. Numeric program encoding. `program_to_nat` and `nat_to_program` round-trip
   full VM instruction lists, but no theorem connects a guest program's final
   register zero to loading and executing the decoded output, and there is no
   inverse from arbitrary decoded VM instructions to well-formed `GInstr`.
3. Existing Rice transformer. `rice_prog pm w` was tested as a possible
   diagonal constructor. It composes a relocated compiled MM2 instance with a
   fixed witness and proves the two reduction cases; it neither represents an
   arbitrary supplied transformer `F` nor produces `p` with `p ~= F p`.

What would unblock the target is a closed guest-level universal evaluator for
`guest_program_code`, or an s-m-n theorem derived from such execution, plus
correctness tying the resulting wrapper to `g_equiv`.

## Hollowness checks

### `vm_guest_recursion_theorem`

- Definitional: the target is a genuine behavioral fixed point, not a
  syntactic self-copy definition.
- Built in: representability only states that `D` returns a code; it does not
  grant execution of that code.
- Vacuity: `identity_transformer_representable` is a closed inhabitant of the
  representability premise, so the interface is satisfiable.
- Swap test: L has a separately derived recursion theorem, but no verified
  compiler from L terms to this guest execution exists; substituting L would
  change the named machine.
- Adversarial read: PASS on the exact BLOCKED statement and obstacle.

### `vm_guest_rice`

- Definitional: not a restatement; it uses a concrete reduction and the
  behavior of `rice_prog` in the halting and nonhalting cases.
- Built in: extensionality and nontriviality are premises, but undecidability
  is not assumed.
- Vacuity: the existing `g_halts_on_zero_undecidable` instantiation supplies a
  well-formed satisfying program and proves `g_bottom` does not halt.
- Swap test: the theorem ranges over every extensional property satisfying the
  boundary, rather than a property selected by name.
- Adversarial read: PASS; the sentence does not claim derivation from the
  blocked recursion theorem.

The semantic test was observed red before the target, audit, and report
existed. The successful wrappers then compiled with no global assumptions.
The recursion prediction and Rice prediction were both correct. No novelty
claim is made.

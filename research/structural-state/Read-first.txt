Question: How much protected state does an exact online monitor need, and how
does that interact with update time and claim expressiveness?

Concrete guarantee studied: USE(i) must succeed exactly when a trusted PASS(i)
has occurred since the last write to any declared dependency of claim i.
Every write is mediated; validation and use are atomic with respect to writes.
Soundness and completeness are both required. This is a freshness guarantee,
not a claim that every epistemic invariant reduces to freshness.

Results:
1. Exactly n persistent bits are necessary and sufficient when n separately
   queryable freshness statuses vary independently at identical public data.
2. Global invalidation has a sharp known threshold: with exactly n persistent
   bits a worst-case reset costs Omega(n/w) word writes; n+1 persistent bits
   permit constant-time reset, insertion and membership using Hagerup's choice
   dictionary, with O(w) temporary workspace and externally available n.
3. Arbitrary dependency overlap can encode online Boolean matrix-vector
   multiplication. With near-quadratic preprocessing, making PASS, WRITE and
   USE all O(n^(1-epsilon)) for a fixed epsilon>0 would refute the OMv conjecture.
4. An eager n-bit monitor has constant PASS/USE and O(ceil(n/w)) dense WRITE.
   A bounded lazy monitor uses O((n+m)log(n+m+1)) persistent bits, constant
   amortized PASS/WRITE, and O(1+|D_i|) USE. Neither needs unbounded counters.

These are proved reductions and constructions, with existing results credited.
They do not establish novelty or the complete tight memory/time frontier.
Actual predicate validation cost is additional to metadata maintenance.

The next precise research target is to characterize dependency families that
admit n+O(w) persistent protected bits and constant worst-case PASS, WRITE and
USE, with preprocessing near-linear in an explicit policy representation.
Global invalidation and bounded write fan-out give positive examples; arbitrary
overlap has the conditional obstruction above. Existing dynamic set-query
classification results must be compared before claiming a new classification.

STRUCTURE, ESTABLISHMENT, AND EXECUTION COST
Research note for Devon Thiele — 12 October 2026

STATUS AND SCOPE

This note gives mathematical proofs about the partition example already in
The Thiele Machine. It does not propose another machine architecture. It asks
which information can be identified without changing the example's behavior.
The proofs stand independently of their finite executable checks.

The source correspondence is minimal/PartitionReading.v at repository commit
e4c234627651f1b12eb649148a051d5a252ed6b4. No manuscript or repository source
is changed. This is a focused result, not a completed audit of the book.

The result has three parts:

  1. The mathematical consequences of a collection of checked groupings have
     an exact summary: one partition, their join.
  2. That summary cannot in general preserve the existing rule about which
     groupings may be committed. A sharp family of examples needs t-1 bits
     to distinguish histories with identical mathematical consequences,
     where t is the number of available partition claims.
  3. Structural effects alone cannot determine the existing execution bill.
     Repeated successful checks can leave the structure unchanged while
     adding to the ledger. Paths or an accumulated ledger must retain this
     distinction.

These are consequences of explicit observation and action contracts. The
partition-lattice and distinguishable-history arguments are classical tools;
no claim of a new general lower-bound technique or open-problem solution is
made. The substantive application is to this existing structural example.

1. THE EXPERIMENT

Put three objects a, b, c on a table. Each carries a key, such as a color.
A grouping claims that objects placed in the same bucket have the same key.
The claim does not say that different buckets must have different keys.

Compare two runs when all three objects have the same key:

  Run A: check {a,b,c}; then check {a,b,c} again.
  Run B: check {a,b,c}; then check {a,b}|{c}.

Both runs have established the same mathematical consequences: all three
keys agree, which already implies agreement within any smaller bucket.
Both have performed two successful checks and paid two marks. Neither has
committed or raised a record.

Now request COMMIT {a,b}|{c}.

  Run A traps. Run B succeeds.

This is exactly the existing rule: COMMIT requires a matching partition in
the checked table. It does not merely ask whether that partition follows
logically from earlier checks. Renaming buckets does not matter; checking a
different partition does.

The example therefore distinguishes two questions:

  What follows from the established constraints?
  Which action has been earned under the specified history rule?

Their answers can differ without either being inconsistent. Treating them
as interchangeable changes the machine. This distinction is a policy in the
existing model, not a universal requirement that every computation must use.

2. THE MATHEMATICAL SETUP

Let X be a finite nonempty set of n items. A partition P is represented by its
equivalence relation E_P: x E_P y means x and y occupy the same bucket.
Write P <= Q when E_P is contained in E_Q. Thus P is finer than Q.

Bottom, denoted 0, separates every item. Top, denoted 1, puts all items into
one bucket. These symbols denote partitions, not instruction prices.

A key assignment k induces the partition K defined by equality of keys.
The grouping P is sound for k exactly when P <= K. Every partition K can
occur as a key partition: give distinct keys to its distinct blocks.

For a finite set T of checked partitions, define J(T) to be their join:
the equivalence closure of the union of their equivalence relations.
For T empty, J(T)=0. It is the least partition coarser than every member
of T. This is a mathematical operation, not a claim about its runtime.

The information expressed by T means only its soundness assertions. It does
not include the actual key assignment, the table's membership as a historical
fact, an external transcript, or the timing of the checks.

3. EXACT SUMMARY OF THE MATHEMATICAL CONSEQUENCES

Theorem 1. For any checked family T and proposed grouping H,

  for every key partition K,
    [P <= K for every P in T] implies H <= K

  if and only if H <= J(T).

Proof. The conjunction P <= K for all P in T is equivalent to J(T) <= K
by the defining property of the join. If H <= J(T), transitivity proves
the implication. Conversely choose K=J(T). It satisfies every assertion
in T, so the implication forces H <= J(T). Such a K is realizable by an
actual assignment of keys. This proves both directions. End proof.

Consequently the entire set of mathematical consequences is the set of
refinements of J(T). Two checked families have the same consequences if
and only if their joins agree. For the reverse direction, each join belongs
to its own refinement set, so equality of those sets gives both refinement
directions and hence equality of the partitions.

This generalizes the existing single-grouping entitlement result to any
finite collection of checked groupings. A chain example makes the join
visible: checking {a,b}|{c} and {a}|{b,c} establishes a=b and b=c, hence all
three keys agree. Neither individual grouping asserted the full result.

This is implication among the specified equality claims. It does not assert
that computation always contracts possibilities, or that a unique answer or
termination follows. SET can discard the checks against the previous key.

4. AN EXACT STRUCTURAL REPRESENTATION OF THE EXISTING RULES

Replace each grouping and key by its partition on X. Replace the checked
list by the SET of its distinct partitions. Retain:

  K: the current key partition;
  T: the set of partitions checked against the current key;
  C: an optional committed partition;
  R: an optional pair (partition, historical key partition);
  e: the trap flag;
  m: the accumulated ledger.

The permitted observations are structural: these canonical partitions and
checked membership, the channel, historical record, trap, and ledger.
Numerical bucket/key labels, checked-list order and duplicate multiplicity
are not separately observable. Action parameters are canonicalized in the
same way. This is a declared interface, not equality of raw source records.

For an untrapped state, the rules become:

  SET K':     K := K'; T := empty; C := none. Retain R. Cost 0.
  CHECK P:    if P <= K, add P to T; otherwise trap. Cost 1 either way.
  COMMIT P:   if P belongs to T, set C := P; otherwise trap. Cost 1.
  CERTIFY:    if C is none, trap; otherwise, if R is none, set R := (C,K).
              If R already exists, retain that first record. Cost 1.

On an already trapped state, only the ledger changes, by the action's cost.
In particular SET cannot recover a trapped state. Retaining the historical
record across SET does not make it a claim about the new current key.

Theorem 2. Canonicalization commutes with every step, preserves its price,
and therefore preserves every finite trace of the stated observations.

Proof. Equality of numerical keys becomes equality in K; the CHECK test is
exactly P <= K. The source COMMIT test searches for a grouping inducing the
same partition, which is exactly membership in T. Prepending a successful
check becomes set insertion. SET clears the same fields; the channel and
first historical record are transformed componentwise. Trap and ledger
updates agree in each branch, including already trapped states. This proves
the one-step identity. Induction on the action sequence proves the trace
statement. End proof.

This representation removes bucket names, list order and duplicates from
stored structural information. It retains the distinction between separately
checked partitions. Replacing T by J(T) alone is not an exact implementation
of these rules: the experiment in Section 1 disproves that possibility,
even when the other fields, including the ledger, are supplied.

If COMMIT were instead defined to accept any H <= J(T), the join WOULD be
sufficient for that guard. That would be an inference-permitting policy,
not a compression preserving the present exact-check policy. Neither
policy is established as universally preferable by this result.

5. A SHARP STATE REQUIREMENT WITH IDENTICAL CONSEQUENCES

Let L be a finite language of t DISTINCT partitions of X, including the
one-bucket partition 1. COMMIT may request any member of L. Consider all
histories starting from the same clean state with K=1 and ledger zero.

Theorem 3. There are 2^(t-1) reachable, pairwise distinguishable states with
the same current key, mathematical consequences, channel, historical record,
trap status, ledger and number of executed steps. An exact deterministic
implementation must have at least that many distinguishable retained states
at this boundary. With no other history carrier, this requires at least
t-1 bits. The bound is attained for this family by its membership vector.

Proof. For every subset U of L excluding 1, perform CHECK 1, then check
each member of U in a fixed order, then repeat CHECK 1 until exactly t
checks have been performed. All checks succeed because every partition
refines K=1. The resulting checked set is {1} union U.

All these states have K=1, C=none, R=none, e=false and m=t. Each has join
1 and therefore exactly the same mathematical consequences. The programs
can have the same length and a common next request; their earlier action
parameters must not be provided as a free external history at the boundary.

For U different from V, choose P in their symmetric difference. The common
next action COMMIT P succeeds for one state and traps for the other. If an
implementation assigned both histories the same complete retained state,
it could not produce different deterministic answers to that same request.
Thus all 2^(t-1) states must remain distinct. A representation with b bits
has at most 2^b states, so b >= t-1.

Conversely, one bit for membership of each partition other than 1 identifies
every state in this family, since membership of 1 is fixed. It answers every
COMMIT membership question on this family. This proves sharpness for the
family, not a total-memory optimum for all machine operations. End proof.

If L contains every partition of n items, t is the Bell number B_n:

  items n                 1     2     3     4     5
  partition claims B_n    1     2     5    15    52
  required bits B_n-1     0     1     4    14    51

For comparison, one semantic summary partition has only B_n possibilities;
its abstract identity can be encoded in ceil(log2 B_n) bits. This statement
is about distinguishable possibilities, not efficient encoding or update
time. On the particular lower-bound family the semantic summary is always
1 and itself requires no varying information at all.

The bound counts all retained information available for exact decisions.
It becomes a protected-memory bound only if no other usable history carrier
is available. An authenticated external table, recoverable action transcript
or trusted caller state must be counted or treated as a different interface.
The theorem supplies no time-space trade-off, randomized error bound, or
unconditional lower bound for arbitrary cryptographic outsourcing schemes.

Most importantly, it is a cost of enforcing THIS establishment rule, not an
inherent Bell-number memory requirement for truth, structure, or computation.
Allowing entailed commitments changes the rule and avoids this particular
distinguishability family. This is precisely why the interface matters.

6. WHY THE BILL CANNOT BE READ FROM STRUCTURAL EFFECTS

Remove m from the representation in Section 4, but keep the other fields.
Let s be a clean state where P is sound. One successful CHECK P and two
successive successful CHECK P instructions produce the same structural state:
same K, checked set {P}, empty channel and record, and no trap.
Their costs are 1 and 2. Thus no function of that final structural state
alone recovers the accumulated bill for these histories.

The same obstruction can be expressed at the level of transformation rules.
On states with fixed K where P is sound, CHECK P inserts P in a set and is
an idempotent structural map F: F composed with F equals F. An additive cost
on extensional maps with finite nonnegative integer or real values would
have to satisfy

  cost(F) = cost(F composed with F) = cost(F) + cost(F),

and hence cost(F)=0. It cannot assign the existing price 1 to that map.

Execution paths resolve this without a contradiction: [CHECK P] and
[CHECK P, CHECK P] are different paths, despite having the same structural
effect. Assign each executed edge its price and add along paths. Equivalently
retain an accumulated ledger as a separate state component. With the ledger
retained, the full CHECK transformation is not idempotent.

For fixed finite X the structural representation without m is finite, even
though arbitrarily many duplicate checks may be executed. A positive-cost
self-loop shows why an unbounded cumulative ledger cannot be reconstructed
as a state function on that finite structural representation.

More generally, an additive path cost descends through an identification of
paths if and only if identified paths have equal cost. Necessity follows
from well-definedness; sufficiency assigns each class its representatives'
common cost. To retain composition, the identification must also respect
composition. Positive reset prices therefore cannot be inferred merely by
calling structural maps morphisms and their costs a functor.

None of this proves a heat floor or a necessary positive price for CHECK.
The price here is the existing operational ledger rule. Physical dissipation
requires additional physical assumptions and uncertainty accounting.

7. INFERENCE POLICIES: A PRECISE ALTERNATIVE AND ITS PRICE

The source's exact-match rule is one possible establishment policy. A useful
comparison permits a commitment inferred from successful current checks.
This section analyzes that alternative; it does not install it in the book
or silently treat it as equivalent to the source.

There is a catch. The discrete partition 0 is sound for every key, without
any checks. Under the unqualified entailment guard H <= J(T), a clean
machine could COMMIT 0 and CERTIFY for two marks. Consequently replacing
the guard alone would invalidate the existing three-mark floor.

If a successful current check is required, retain an evidence-presence flag
A, which says T is nonempty. Permit COMMIT H only when A is true and
H <= J(T). A successful CHECK sets A=true and updates J by joining its
partition. SET resets A=false, J=0 and the channel. The historical record,
trap behavior and prices remain as specified earlier.

The flag cannot always be recovered from J: no checks and a successful
CHECK 0 both have join 0. But they must give different COMMIT 0 decisions
under this anchored policy. No claim of nontriviality follows from the flag;
CHECK 0 is still a successful, tautological check.

This construction extends beyond full entailment. Let L be a finite claim
language and let c map subsets of L to subsets of L. Require c to be:

  extensive:   T is contained in c(T);
  monotone:    T contained in U implies c(T) contained in c(U);
  idempotent:  c(c(T)) = c(T);
  sound:       every member of c(T) follows from the soundness claims in T.

These properties define a sound closure policy. The identity c(T)=T gives
exact matching. For partition claims, c(T)={H in L : H <= J(T)} gives full
semantic entailment. Soundness is relative to the stated interpretation of
the claims, not supplied merely by the other three algebraic properties.

Theorem 4. For the policy permitting COMMIT H exactly when T is nonempty
and H belongs to c(T), the pair (A,c(T)) is a sufficient online replacement
for T, with the other structural fields and priced actions retained.
It preserves the altered policy's behavior and soundness, and its minimum
cost to raise a first record from a clean zero-ledger state is still three,
whenever at least one claim can successfully be checked.

Proof. The closure axioms give

  c(T union {P}) = c(c(T) union {P}).

For one inclusion use T contained in c(T) and monotonicity. For the other,
both c(T) and {P} are contained in c(T union {P}); apply monotonicity and
idempotence. Thus CHECK updates the stored closure using only that closure
and its argument. SET resets it to c(empty) and clears A and the channel.
The COMMIT guard is determined by A and membership in the stored closure.
Other branches are unchanged. This proves step preservation as in Theorem 2.

Every member of T is sound for the current key. Soundness of c makes every
authorized commitment sound for that key too. The first historical record
therefore stores a sound claim and its historical key, even after later SETs.

The first successful CERTIFY needs a channel produced by COMMIT. That COMMIT
needs A=true, which requires an earlier successful CHECK since the latest
SET, if any. These are three distinct paid actions in order. Conversely,
CHECK P; COMMIT P; CERTIFY succeeds for a sound P because c is extensive.
It costs exactly three. End proof.

The provenance statement changes: an inferred committed claim need not have
been checked verbatim. It must follow from the actual collection of current
checks. This is an explicit policy difference, not the original same-claim
theorem under different notation. Theorem 4 supplies no computational time
bound for evaluating c, and not every inference mechanism is a closure of
this kind.

There is a sharp comparison for the language of all B_n partitions, with
the current key fixed to 1. Count only the retained component needed for
these permission decisions, with all other fields supplied and fixed in
the lower-bound experiment.

Theorem 5. The source's exact-match policy requires exactly 2^(B_n) possible
permission states, or B_n bits. The anchored full-entailment policy requires
exactly B_n+1 possible permission states, or ceil(log2(B_n+1)) bits. These
are abstract state counts and fixed-width encoding bounds, not update-time
bounds or total implementation memory bounds.

Proof for exact matching. Every subset T of the B_n claims is possible.
Distinct subsets differ on a COMMIT request. A membership vector attains
2^(B_n) states, establishing necessity and sufficiency.

To make the necessity hold with equal ledgers and equal action counts, put
t=B_n. For any nonempty T, first SET the key to 1, check every member of T,
then repeat one member until t checks have occurred. For T empty, check 1
t times and then SET the key to 1. All histories have t+1 actions, ledger t,
key 1, no channel or record, and no trap. Only the retained checked sets
vary. Thus the supplied common fields cannot encode their differences.

Proof for anchored entailment. If A=false, the only possible summary is
J=0. If A=true, J can be any of the B_n partitions. These B_n+1 states are
sufficient by Theorem 4. Each is reachable with the same common fields,
ledger and action count using the preceding construction with T empty or
T={J}. Two distinct active joins have different refinement sets, so some
COMMIT H distinguishes them. The inactive state rejects COMMIT 0, whereas
every active state accepts it. All states are therefore distinguishable.
End proof.

For three objects this comparison is five permission bits versus three;
for five objects it is fifty-two versus six. The difference is accounted
for by what the rule promises to remember: exact checking history or its
logical consequences plus the presence of a current check. Neither policy
receives a lower runtime or physical-energy bound from these state counts.
As in Theorem 3, external usable history must be counted or excluded before
calling this a protected-memory lower bound.

8. WHAT THIS SETTLES, AND WHAT IT DOES NOT

The partition model has an exact answer to a representation question:

  Mathematical consequences may be compressed to a join partition.
  Exact earned permissions may still require the distinct checked set.
  Execution costs require priced paths or a ledger when equal effects can
  arise from differently priced executions.

Those are three different equivalence relations on histories. A proposed
abstract representation must state which it preserves. If it identifies
histories separated by an allowed future observation, it changes the model.

This is independent of counter machines and numerical bucket names. It is
not a claim that standard computation cannot represent these distinctions;
the construction explicitly shows how to represent them. Nor does it derive
the choice of establishment policy or the positive ledger prices from the
partition geometry alone.

For sound closure policies, Theorem 4 answers how to preserve the connection
between actual checks and subsequent inferred actions. Theorem 5 gives a
tight state comparison for two such policies on this partition language.
The remaining time-space question requires a computational model for the
closure operation and claim representation; state counting alone does not
answer it. Any broader lower bound must also specify available external
history and the observations it promises to preserve.

rules and a separate partition-and-set implementation. It checks step

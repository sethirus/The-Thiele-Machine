WHAT A FAITHFUL IMPLEMENTATION OF THE SMALL MACHINE MUST PRESERVE
Research working note for Devon Thiele — 12 October 2026

PURPOSE AND STATUS

This note returns to the actual Small Machine. It keeps CHECK, COMMIT,
CERTIFY, the two counters, the permanent record, the commitment channel,
the 16-slot fact table, trapping, and the ledger. It asks which distinctions
an implementation must retain to reproduce their behavior, and what follows
when a mutation removes those distinctions from the operational interface.

Results:
1. Any exact implementation must separate histories that some common future
   instruction sequence distinguishes. This is the classical continuation-
   equivalence/minimal-realization argument, applied here; it is not new.
2. The Small Machine has 81 pairwise distinguishable permission states with
   identical counters, current version numbers, pc, ledger, record, channel,
   and ordered claim names. A single COMMIT separates every pair.
3. For the stated operational interface, unbounded version labels can be
   replaced by two live-prefix lengths, together encodable in seven bits.
   This is a step-for-step representation theorem for the whole instruction
   system under that interface, not a replacement freshness-only specification.
   A second representation additionally preserves equality and order among
   old fact editions, current editions and the channel's historical edition.
   It uses at most 16 edition-gap bits, rather than discarding those relations.
4. A four-instruction, zero-ledger cycle resets all 81 permission states to
   one operational state. Exact behavior does not require implementations to
   forget their hidden history. If a deterministic implementation retains all
   distinctions reversibly for T repetitions, its boundary-state capacity M
   must satisfy M >= 1 + 80(T+1). With the richer edition-relation interface,
   the corresponding full 16-gap experiment gives M >= 65536 + 49152T.
   The general reset-only bound is tight.

The arithmetic and finite examples have executable checks. The proofs below
are the basis for the general statements. Literature priority for the specific
machine application has not been established. No claim that a major open
problem has been solved is made. The existing book already contains related
window-separation, descent, and finite-permanence arguments.

1. THE ACTUAL SEMANTICS

The inspected reference is minimal/EarnedCore.v at repository commit
e4c234627651f1b12eb649148a051d5a252ed6b4. Its executable mathematical rules are:

State: counter values A,B; versions v_A,v_B; program counter pc; newest-first
fact list; optional commitment channel; trap flag; ledger mu; permanent flag.
A fact is (property, counter, version). The property language includes Zero,
Even and Ge(k). COMMIT uses exact property identity, not logical implication.

INC changes a counter and increments its version. A positive DEC also writes
and increments the version; DEC of zero only advances pc. CHECK evaluates its
property and, if true with a free slot, prepends the current-version fact.
Otherwise it traps. Duplicate CHECKs occupy separate slots. Stale facts are
not removed: even a table full of stale facts rejects the next CHECK.

COMMIT succeeds exactly when an equal current-version fact occurs in the
table, then places that fact in the channel. CERTIFY succeeds when the channel
is nonempty and the machine is not trapped. The flag stays up thereafter.

A later write DOES NOT empty the channel. For example:

  start A=0
  CHECK Zero A; COMMIT Zero A; INC A; CERTIFY

ends with the flag up, A=1, and a historical commitment to the earlier A=0.
Another COMMIT Zero A now fails. Fresh authority to make a new commitment
and the persistence of an already earned commitment are different things.
There is no new freshness test between COMMIT and CERTIFY in these rules.

CHECK, COMMIT and CERTIFY each add one to mu; other instructions add zero.
The direct instruction semantics charges even a failed or post-trap charged
instruction. In stored-program execution a trap stops instruction fetching,
so no further instruction is executed or charged. The experiments preserve
both conventions rather than conflating them.

2. WHAT COUNTS AS PRESERVING THE MACHINE?

Fix an interface before claiming an implementation is faithful. Here it admits
all six instruction forms and observes, after each instruction:

  (A, B, pc, trap, ledger, permanent flag,
   ordered list of (property,counter) fact names,
   optional (property,counter) name of the last commitment).

Thus it preserves more than a final answer: it preserves successful and
failed actions, duplicate slots and capacity, claim identity, ordering,
historical commitment, the permanent record, and exact ledger evolution.

This interface DOES NOT export numeric version labels, comparisons between
the versions of arbitrary old facts, or an unbounded write count. The source
defines state projections that can expose these; this theorem is not a
claim of full-state equality or equivalence for such an expanded interface.
An external audit API that requires those data needs a separate representation
theorem. Nor does this interface purport to formalize every structural concept
discussed throughout the book. It is the complete instruction behavior of this
concrete machine under the explicitly listed observations.

Allow an implementation to take any finite number of internal steps per
instruction. Compare states at instruction boundaries. It is faithful when,
for every allowed history and every next instruction, it produces exactly the
specified next observation and remains able to continue faithfully. The
implementation may use different data structures and may retain extra history.
An adversarial program may choose its instructions, but may not bypass the
machine's transition rule and directly forge protected facts or the channel.
An implementation that permits that does not meet the specified behavior.

All history carriers count. A trusted transcript, a controller, an input head
that reveals elapsed history, a clock, host memory, and a differing program
can each distinguish executions. They cannot be supplied for free while a
lower bound counts only some other register. The experiments use a common
future instruction stream; earlier supplied instructions are not available as
an uncharged trusted replay log. We are not claiming that one deterministic
closed program, from one fixed complete state, has several different runs.

3. THE PRESERVATION THEOREM

Call histories h and k equivalent when every finite common continuation gives
the same sequence of interface observations after h and after k, including
the current observation. Otherwise call them distinguishable.

Theorem 1. Any deterministic faithful implementation must end in different
complete accessible implementation states after distinguishable histories.

Proof. If its states were equal and its subsequent inputs the same, its next
transition and response would be the same. Induction gives equal responses
through any finite continuation, contradicting a distinguishing continuation.
The implementation can put the distinction anywhere in its counted state;
renaming fields or recomputing from retained history cannot eliminate it.

Consequently K pairwise distinguishable histories require at least K states.
If every other accessible component is held fixed and the remaining protected
representation contains B bits, then 2^B >= K. If an external component keeps
the distinctions, this is a bound on that combined representation instead.

Conversely, equivalence is stable under appending the same instruction. Its
classes therefore define a deterministic transition system that preserves
the interface: execute by appending the instruction and taking the resulting
class. This characterizes the smallest state distinction in the abstract.
It need not yield an effective minimization procedure for an infinite-state
machine, nor efficient algorithms for finding or updating classes.

This is the familiar minimal-realization/Myhill-Nerode reasoning. The value
here is the actual Small Machine witnesses and the exact interface, not a
claim to have discovered distinguishability or automaton minimization.

4. A NORMAL FORM THAT PRESERVES THE INSTRUCTION SYSTEM

Consider states reachable from start(A,B). For each counter, restrict the
newest-first fact list to the facts concerning that counter. Their numeric
versions are nonincreasing, and none exceeds the current version. Therefore
the current-version facts form a prefix of that counter's subsequence.

Let r_A and r_B be those prefix lengths. Define alpha(s) by retaining all
fields from section 2, dropping numeric versions, and adding (r_A,r_B).
The reduced transition rules are:

  INC / positive DEC of c: perform the original value/pc update; set r_c=0.
  DEC of zero: advance pc and leave both prefix lengths unchanged.
  Successful CHECK p c: prepend (p,c), increase r_c by one, advance pc.
  Failed CHECK: trap, including when the 16-slot table is full.
  COMMIT p c: search the first r_c entries in c's fact subsequence for p;
              on a match update the channel to (p,c), otherwise trap.
  CERTIFY: use exactly the original nonempty-channel/trap test.
  HALT, traps, the ledger and the permanent latch: retain the original rules.

Theorem 2. For every reachable reference state s and instruction i,

            alpha(exec(s,i)) = reduced_exec(alpha(s),i).

Proof. Initially the fact list is empty and both lengths are zero. CHECK
records the current version, so it adds exactly one new current fact at the
front of its counter's subsequence. A write strictly increases that counter's
version, so every existing fact for it becomes old; none can become current
by accident. The other counter's subsequence is unchanged. No other instruction
changes versions or facts. These observations prove the prefix invariant.

CHECK's truth, capacity and trap tests use retained data. The invariant makes
the two COMMIT membership tests equivalent. Their channel claim names agree.
CERTIFY depends only on channel occupancy and the trap flag, both retained.
All remaining value, pc, flag and ledger updates are identical. Checking the
instruction cases gives the displayed equality, including failure and trapped
states. Induction extends it to every finite instruction stream. Since pc,
HALT and trapping are preserved, identical stored programs fetch identical
instructions, giving the same result for stored-program runs.

The same executed history still supplies the CHECK -> COMMIT -> CERTIFY
witness. A successful reduced COMMIT refers to a successful earlier CHECK of
the same property and counter with no intervening write to that counter.
The channel may persist through later writes, just as in the reference.
The reduced state need not contain an explicit copy of the entire witness
history in order for this invariant about its execution to hold.

Every instruction has the original ledger increment. Thus the machine's
three-mark minimum and its attained three-instruction example are preserved
as statements about that specified ledger. This does not derive those prices
from physics or from implementation time.

If a facts concern A and b concern B, the live-prefix pair has at most
(a+1)(b+1) possibilities. With a+b<=16, this product is at most 81, attained
at a=b=8. The code r_A+(a+1)r_B represents it in seven bits, using the fact
names to recover a. This bounds ONLY the additional edition/freshness
distinction. Claim parameters, values, pc and the ledger can still be
unbounded; the entire machine is not a seven-bit or finite-state machine.

Numeric editions are therefore one sufficient representation of these
operational distinctions, not intrinsically required unbounded storage for
this interface. Old-fact version-equality audit questions would change that
conclusion's scope, as stated in section 2.

4A. KEEPING HISTORICAL EDITION RELATIONS AS WELL

The seven-bit representation intentionally forgets which OLD checks concern
the same old edition. That information is present in the reference state.
To avoid silently discarding it, consider a richer interface that additionally
observes equality and order of editions within each counter's facts, their
relation to the current edition, and the channel's historical edition relative
to those facts. These are specified audit observations, not newly claimed
existing instruction forms. They do not report the numeric write count or
compare the numeric labels of unrelated counters.

There is a bounded normal form for this interface too. For each counter,
collect the distinct versions appearing in its stored facts together with
its current version. Replace them in increasing order by 0,1,... . The
channel's fact always occurs in the never-deleted table, so replace its label
using the same map. Keep every other field.

These canonical ranks evolve without an unbounded counter. A successful
CHECK stores the current rank. A write increases the current rank by one
if any stored fact uses it; otherwise it leaves the current rank unchanged.
All other tests and transitions are the original ones on these ranks.

Why it works: after a write, the old current version remains in the ranked
set exactly when a stored fact names it. If it remains, the new current
version gets the next rank; if it does not, replacing the greatest version
by a newer greatest version does not change any rank. CHECK only copies a
rank already present. COMMIT's equality test and the historical channel are
therefore preserved exactly under rank normalization. Instruction case analysis
and induction give the same commuting diagram as Theorem 2 for this richer
interface. The executable edition_abstract / edition_step check this claim.

The complete edition relation has a particularly small encoding. In the
chronological fact subsequence for one counter, place a bit after each fact:
one means its version differs from the next fact's version, or from the current
version after the last fact; zero means they agree. Cumulative sums of these
gap bits reconstruct every canonical rank. With sixteen total facts, at most
sixteen bits encode all these within-counter edition relations. If the channel
is stored by a table-slot reference, an additional five bits distinguish empty
from any of the sixteen slots. These are component bounds, not full machine
space bounds; the executable model uses explicit ranks rather than bit packing.

Every one of the 2^16 gap patterns is reachable with eight facts per counter
and the same ordinary data and current numeric versions. For each counter,
put an INC/DEC pair after exactly those checks whose gap bit is one. Put the
remaining pairs before its first check, so exactly eight pairs execute for
that counter. Check Ge(1),...,Ge(8) from value 8. All histories end with
A=B=8, v_A=v_B=16, pc=49, ledger=16, the same claim names, empty channel,
record down and no trap. Comparing a differing neighboring-edition pair
distinguishes unequal gap patterns in the richer interface. Thus the sixteen
bits' worth of edition distinction are also necessary in this fixed context.

The reset cycle R below sets the final gap for each counter to one and keeps
all earlier gaps unchanged. It therefore has 65536 input relation states and
16384 fixed output relation states, with four inputs per output. This supports
the richer-interface retention bound in section 7 without discarding old-fact
relationships just to make a stronger collapse appear.

5. THE 81 DISTINCT HISTORIES: THE LOWER BOUND IS REALIZED

First see the two-history case. Start A=8. In one history, increment A,
decrement it back to 8, THEN check A>=8. In the other, check A>=8 FIRST,
then perform the increment and decrement. Choose jumps so both finish on the
same line. Both finish with A=8, version 2, one fact naming A>=8, ledger 1,
no commitment and a lowered record. The statement A>=8 is true in both.
COMMIT Ge(8) A must succeed only in the first. This is the difference the
machine requires an implementation to retain. A test of present values
alone cannot reproduce it.

Start from A=B=8, both versions zero, an empty table/channel, ledger zero and
record down. For each counter c, perform the eight successful checks

               c>=1, c>=2, ..., c>=8.

Insert exactly one INC c; DEC c pair at a chosen cut in those eight checks.
The pair restores the counter's value and advances its version twice. Pick
the DEC jump to continue to the next line. Do all A checks before all B checks.

If the pair is placed after 8-r_c checks, precisely the final r_c checks
still concern the current version. Each r_c can be any integer from 0 to 8.
Every resulting history has length 20 and ends with:

  A=B=8; v_A=v_B=2; pc=21; mu=16;
  the same ordered sixteen property/counter names;
  empty channel; record down; no trap.

Only which fact editions are current differs. There are 9*9=81 choices.
For any unequal choices, select a counter with unequal r values and a checked
property in the difference between their live suffixes of chronological checks.
COMMIT of that exact claim succeeds in one state and traps in the other.
All current numerical predicates are true in both states. Re-evaluating their
truth therefore cannot replace this distinction about what was established
since mutation.

Theorem 1 requires at least 81 implementation states within this shared
visible situation, hence seven bits' worth of distinguishability. The normal
form attains that bound for this component, conditional on the other retained
fields. It is not a demand for seven separately addressed hardware bits: a
nonsystematic encoding can distribute the distinctions through its storage.

This directly sharpens the earlier independent-freshness abstraction. The
sixteen actual table entries do not have 2^16 independently varying fresh
statuses at fixed fact order. Their two chronological prefixes have 81. The
machine's own constraints determine the count.

6. WHAT ORDINARY MUTATION DOES TO THOSE DISTINCTIONS

At the shared pc=21, execute the fixed instruction word R:

         INC A; DEC A 21; INC B; DEC B 21.

After R, A and B and pc have their original values, the same fact names remain,
and both live-prefix lengths are zero. Channel, trap and permanent flag remain
unchanged. All four instructions cost zero in the specified ledger.

Thus R takes all 81 seven-bit-normal-form states to the same reduced state, and repeating R
keeps that state unchanged. In the full reference, numeric versions continue
to grow and old fact stamps remain, retaining distinctions discarded by alpha.
The reference implementation is not being accused of erasing those stamps.

The reduced implementation and the reference agree on the whole interface
and ledger, but differ in which internal distinctions their transitions lose.
Consequently the location and amount of implementation-level merging are not
determined by this operational interface and ledger alone.

This does not contradict the book's record-layer pricing premise: it is not
a claim that the two states agree on that premise's entire base configuration.
Nor is the Toll a stated charge on every kind of garbage collection. It does
rule out silently equating this ledger with all information an arbitrary
implementation physically discards.

7. A SHARP FINITE-HORIZON RETENTION BOUND

The following theorem concerns a reset experiment. It gives a quantitative
version of the finite-permanence obstruction, not a new general physical law.

Let q_0,...,q_(N-1) be distinguishable abstract states. A fixed operation R
maps every one to q_0 and keeps q_0 there. Choose one implementation state
x_i representing each q_i. Let F be the deterministic implementation of R,
sampled at operation boundaries. Repeated uses apply the SAME F: there is
no free external phase counter. Suppose there are at most M possible counted
implementation states at these boundaries.

For an integer T>=0 define

             D_T = { F^t(x_i) : 0<=i<N, 0<=t<T }.

Assume F is injective on this UNION of reachable input states. Requiring
injectivity separately at each time is weaker and is not the assumption.
Reversible retention here means injectivity of the OPERATION-BOUNDARY map F.
A microscopic realization must justify that property, for example through
a reversible return protocol. Injective microsteps sampled at different,
unrecorded stopping times do not by themselves establish it. If a clock or
timing channel changes F or retains a distinction, its state must be counted.

Theorem 3. For N>=2,

                   M >= 1 + (T+1)(N-1).

Proof. For each i>0, the trajectory x_i,F(x_i),...,F^T(x_i) consists of T+1
distinct states. A repetition would, by injectivity on D_T, cancel equal
numbers of applications of F until x_i equalled a positive iterate. But x_i
represents q_i and every positive iterate represents q_0, a contradiction.
The same cancellation argument shows that the N-1 such trajectories are
pairwise disjoint. They already occupy (T+1)(N-1) states.

There is at least one more state. If x_0 is outside those trajectories, use
x_0 itself. Otherwise x_0=F^d(x_i) for some i>0 and 1<=d<=T. Following x_0
through T applications extends that trajectory past F^T(x_i). Its next state
cannot equal any already counted node: it cannot equal a nonzero initial
state because its abstract value is q_0, and every other counted node already
has a predecessor in D_T, so equality would violate injectivity. This supplies
the additional state. For T=0 all N initial states already give the bound.

Tightness for the reset-only experiment. Use one fixed q_0 state z. For each
i>0 make a disjoint path of T+1 states, with only its first state representing
q_i and all others representing q_0. R advances along each path; its final
state loops to itself. The chosen initial states are z and the path starts.
The operation preserves reset semantics forever and is injective on D_T;
at the next horizon it ceases to be injective. There are exactly
1+(T+1)(N-1) states. This proves tightness of the stated experiment, not a
construction for all Small Machine instructions at that same state budget.

For the actual 81-state family and cycle R:

                   M >= 1 + 80(T+1).

If M<=2^B, then B>=ceil(log2(1+80(T+1))). Seven counted bits permit 128 states
and cannot preserve injectivity even through the first reset of this entire
family; eight permit at most two repetitions under this condition. No fixed
finite budget permits indefinitely injective repetition.

General idempotent form. Suppose R acts on N distinguishable abstract states,
has L distinct images, and fixes every image. Apply Theorem 3 separately to
each image's fibre of size k_j. States counted for different fibres are
disjoint, because their abstract states differ. Summing gives the sharp bound

                     M >= N + T(N-L).

Fibre size one contributes its single fixed state. The disjoint path
construction in each fibre proves tightness for this reset-only experiment.
For the richer edition interface of section 4A, N=65536 and L=16384, hence

                     M >= 65536 + 49152T.

Sixteen counted bits suffice to represent all edition relations, but cannot
retain reset history injectively through even the first application across
that full family. Larger finite storage delays the obstruction; it does not
remove it. The numerical theorem concerns total distinguishability capacity
at the fixed boundaries, not an assertion that the entire machine fits into
sixteen bits or that its numeric versions have a fixed finite range.

RESOURCE BOUNDARY. Here M counts ALL implementation states that retain the
distinctions, including discarded work data, time/control state and any
external history carrier. This is not a protected-memory-only heat theorem
when unprotected garbage or an environment can retain information for free.
For the machine application, all other interface fields are fixed at the
boundary; any growing numeric version or hidden clock is part of the counted
variation. The reference's unbounded versions are an explicit escape from a
finite-M hypothesis, not a counterexample to the theorem.

8. WHY THIS STILL DOES NOT PRODUCE AN UNCONDITIONAL HEAT PRICE

Even without this particular normal form, any deterministic transition delta
has an injective history-retaining refinement:

                   (s,h) -> (delta(s,i), h appended with (s,i)).

The last history entry and preceding history recover the source. Projection
onto the first component reproduces the original transition, including the
original ledger and record. This uses growing storage. It does not promise
constant overhead or practical efficiency. It is the elementary mechanism
behind the classical reversible-simulation escape.

Therefore faithful instruction behavior does not by itself force physical
erasure. A finite capacity or reuse constraint can obstruct indefinitely
retaining all distinctions, as Theorem 3 quantifies. A positive thermodynamic
cost still requires the appropriate physical assumptions, input uncertainty,
and accounting for side information and the environment. A pair of possible
inputs that collide is not, alone, a positive heat floor for every actual run.

The strongest justified conclusion here is:
  The specified future actions force distinguishable representations.
  A reset can remove their operational relevance without removing their
  physical history. Retaining that history injectively has a counted capacity
  requirement; forgetting it and pricing that forgetting are separate steps.

9. VALIDATION, RELATION TO EXISTING WORK, AND REMAINING WORK

machine_models.py independently expresses the reference and reduced transitions.
verify.py checks their commutation on exhaustive short histories, longer
histories including full tables, random traces, and stored programs. Explicit
cases cover historical commitment after mutation, failed re-commitment,
duplicate slots, post-trap charging, and the permanent latch. It constructs
all 81 witnesses, finds a separating COMMIT for every pair, and checks that R
has one reduced output and zero ledger increment. It also exhaustively tests
small finite reset maps and the matching path construction for Theorem 3.
The richer edition model is compared on the same instruction histories;
additional witnesses vary every individual gap and sampled joint gaps while
holding total writes fixed. All 65536 abstract gap patterns are enumerated to
check that R has 16384 fixed outputs with four inputs each.
Recorded counts are in verification.json; the successful run is logged.

These are supporting checks, not an independent proof assistant certificate,
a complete audit of the book, or a benchmark for physical implementations.
The reference file's SHA-256 is recorded to make the inspected semantics
identifiable. The proof above does not require access to that repository.

Existing book results: minimal/VerifierSmall.v already proves observation
collisions prevent sound-and-complete verification; ThieleCompleteWindow.v
provides shared-window witnesses; EntitlementSmall.v connects specified
checks, narrowing and ledger hypotheses; the monograph discusses descent
and minimal realization. The new work here is an exact operational normal
form and a concrete many-state witness/retention application, not discovery
of the general observation obstruction.

Classical comparison:
- Myhill-Nerode/minimal realization: distinguishable continuations require
  distinct states. Lecture 5, University of Chicago, CMSC 28000, Winter 2015:
  https://klasses.cs.uchicago.edu/archive/2015/winter/28000-1/Lec5.pdf
- C. H. Bennett, Logical Reversibility of Computation, IBM Journal of Research
  and Development 17(6), 525-532 (1973): retaining information permits reversible
  simulation. The primary paper was inspected. We claim no new reversible-
  simulation result and do not import a heat conclusion from the abstract alone.
  https://worrydream.com/refs/Bennett_1973_-_Logical_Reversibility_of_Computation.pdf

Further work must state which structural observations the broader machine
must preserve beyond this concrete interface. It should then derive the
corresponding distinguishable histories and test whether a price is forced
under an explicit physical or implementation contract. The present work does
not establish that the Thiele Machine exceeds ordinary computability, nor
that its specified ledger is a universal physical law. It does establish
what one complete operational interface requires and an exact obstruction
to retaining its erased distinctions indefinitely in finite state.

INTERVAL INVALIDATION IN n+O(w) PROTECTED BITS
Research working note for Devon Thiele — 12 October 2026

RESULT

For n independently queryable freshness statuses, when each write invalidates
an interval in a supplied static claim order, there is a deterministic exact
online monitor with

  peak protected mutable storage: n+O(w) bits, including temporary workspace;
  PASS, WRITE and USE: O(1+log(1+n/w)) worst-case word-RAM time;
  global invalidation: O(1) worst-case time.

Here n>=1 and w>=max(2,ceil(log2(n+1))); words must also address the allocated
payload, constant-size workspace and static policy. The tiny instances may
therefore require a larger minimum word width for physical addressing.
The guarantee holds for arbitrarily long operation streams. It has no epoch
counter, overflow horizon, probabilistic guarantee or amortized time condition.

This is a construction derived and implemented in these notes. Its ingredients
are familiar: intrusive indexing in unused storage and join-based AVL trees.
Literature priority for this exact combination/bound has NOT been established.
The time bound is not proved optimal. The n-bit information lower bound gives
space optimality only up to an additive constant number of machine words.

The implementation is inplace_monitor.py. The only retained mutable algorithmic
state outside its packed word array is a root identifier. All tree nodes and
temporary traversal frames live in that same word array. Test instrumentation
and the independent verification oracle are not used by the algorithm.

1. SPECIFICATION AND RESOURCES

PASS(i) records a successful trusted check for claim i and sets its freshness
status to one. WRITE(j) clears the statuses in the declared interval [l_j,r_j).
USE(i) returns the current status. All statuses initially equal zero. The lower-
level interface clear_range(l,r) supports any half-open interval, not only the
ones named by a particular static policy.

As in the baseline note, all writes are mediated, PASS cannot be forged, and
events are atomic. A use and its protected action share a linearization point.
Soundness and completeness are both required. The time spent actually checking
a mathematical/data predicate is additional to the PASS metadata operation.

The n status bits are protected mutable metadata. The construction borrows
space INSIDE that protected region. It does not store trusted pointers in
ordinary adversarially writable memory. The code and static policy remain
trusted; their representation and initialization are separate resources.

With a supplied ordering, policy consists of interval endpoints and, if claim
IDs differ from positions, an immutable ID-to-position map. Endpoint lookup
and ID conversion take constant word-RAM time. Their storage P is charged
separately, not hidden inside the mutable-space bound. Computing an ordering
for a dependency family is a separate preprocessing task.

This is logical invalidation. Physical words in a stale region may retain old
bits or hold index data; the interface interprets them as zero. It is not a
secure-erasure construction or a statement about physical heat.

2. THE REPRESENTATION: PUT THE INDEX INSIDE ZERO BLOCKS

Divide the packed status vector into blocks of six w-bit words. A block holds
6w statuses. Let q=ceil(n/(6w)); only the last block may include padding.

A zero block is one whose ENTIRE logical status content is zero. Maintain the
maximal consecutive runs [a,b) of zero blocks in an AVL search tree, keyed by
their starting block a. Distinct runs are disjoint and nonadjacent.

Store a run's tree node in the six words of its FIRST block a. Those words
encode:

  0: exclusive ending block b;
  1: left-child identifier;
  2: right-child identifier;
  3: AVL height;
  4: temporary traversal-frame link;
  5: temporary traversal direction.

There is no separate start-key field: the node's physical address already
determines a. A node identifier is a+1; zero denotes no node. All fields fit
in one word. The final two fields need have no meaningful value between
operations. They cannot affect decoding the statuses.

The representation invariant is:

I1. The tree is a valid AVL search tree on run starts; node addresses are unique.
I2. Its intervals are exactly the maximal runs of completely zero blocks.
I3. Every block outside those intervals stores its logical bits directly, with
    padding zero. Such a block has at least one actual nonzero status bit.
I4. Every node occupies the first block of its own logically zero interval.

Inside a zero interval, all words are semantically ignored as payload. This
includes both current node fields and old abandoned node fields. Outside the
intervals, no node may occupy a block. Therefore index data cannot masquerade
as fresh evidence.

If no zero block exists, the tree is empty. Every word then stores raw status
data and the root equals zero. Thus the construction does not reserve a fixed
fraction of the n-bit array for metadata in the dense case.

3. SEARCH AND RENEWAL

USE(i). Let c=floor(i/(6w)). Find the predecessor run start a<=c in the tree.
If its endpoint b satisfies c<b, return zero. Otherwise read bit i directly
from its data word. A predecessor search takes O(1+log(z+1)) time, where z is
the number of indexed runs. It needs only a constant number of local words.

PASS(i). Locate block c in the same way.
- If c is outside every zero run, set its bit in the raw data word.
- If c lies in [a,b), delete that run from the tree. Insert [a,c) if nonempty,
  with its node still at a. Insert [c+1,b) if nonempty, with its node at c+1.
  Now materialize block c by setting its six words to zero, and set bit i.

The ordering is essential. If c=a, block c housed the old node. That node
must be detached and any remaining right interval indexed elsewhere BEFORE
block c becomes raw data. If a<c, the left interval may reuse the old node at
a, which is distinct from c. If c+1<b, its new node is in a block that remains
logically zero. No external node allocation is required.

This preserves I1–I4. The set of fresh statuses changes only at i. There are
at most one deletion and two insertions, each logarithmic, and six data words
to materialize. Hence PASS has worst-case logarithmic time even after a reset.

4. CLEARING A BLOCK INTERVAL WITHOUT VISITING ITS OLD NODES

First consider clearing whole blocks [a,b). Define add_zero_interval(a,b):

1. If a predecessor interval already covers all of [a,b), return.
2. Split the tree by start a into L (starts<a) and R (starts>=a).
3. If the last interval in L overlaps or touches a, remove it and extend the
   new interval leftward to its start. Preserve the larger endpoint if needed.
4. Split R so that M contains starts<=b and H contains starts>b. Including
   start b coalesces an interval adjacent on the right. Extend the new right
   endpoint to the end of the last interval in M if that is farther right.
5. Abandon M as a whole. Write the new interval's node in its first block,
   which is either a newly cleared block or the removed left neighbour's block.
   Join L, this node, and H into the new tree.

The predecessor-cover check also handles an old interval that spans both
boundaries. Existing intervals are disjoint and nonadjacent, so after extending
to the end of the last interval in M no further interval in H can overlap or
touch the resulting interval.

All nodes in M lie inside the resulting zero run. Their bytes can remain where
they are. There is no allocation map, destructor, reference count, or per-node
freeing operation to execute. They become unreachable from the root in one
structural change, and their logical payload is already zero. If a later PASS
exposes one of their blocks, that whole block is materialized as zero first.

The new node cannot overwrite a surviving node: its block is newly cleared
raw storage, the detached left neighbour, or in the discarded middle range. All endpoints
needed from these nodes are saved before the new node is written.

The operation uses a constant number of AVL searches, splits, a possible
delete-maximum, and a join. Its cost is logarithmic in z+1, independent of the
number of nodes discarded. It adds precisely [a,b) to the set of zero blocks.

5. ARBITRARY BIT INTERVALS

A bit interval [l,r) has at most two partial boundary blocks and a range of
whole blocks in between.

For a partial boundary block:
- If a zero run already covers it, no payload change is needed.
- Otherwise clear the relevant raw bits by masking at most six words. If all
  six words are then zero, add this one-block interval using section 4.

Then clear the complete middle blocks with add_zero_interval. If both bit
boundaries lie in one block, process that block only once. Empty ranges do
nothing. Padding remains zero whenever the final block stores raw data.

This is a constant number of logarithmic tree operations and constant direct
word work. Consequently WRITE is O(1+log(z+1)) worst-case and preserves the
invariant. There is no scan over the whole cleared interval.

Global reset is even simpler: make one node in block zero for [0,q), and set
the root to that node. All other words become ignored payload at once. This
takes constant time with preallocated storage, regardless of previous tree
shape. The Python constructor allocates/initializes a list; that allocation
cost is not an implementation of constant-time allocation. The representation
itself initializes in constant time even over arbitrary old memory.

6. REMOVE THE EXTERNAL RECURSION STACK

A conventional recursive AVL implementation would need O(log q) temporary
words. That would give n+O(w log q) PEAK storage, despite n+O(w) retained state.
The implemented algorithm avoids that extra protected workspace.

Each node provides the two scratch fields described in section 2. During a
tree traversal, push a frame by writing the previous frame's node identifier
and a direction into the current node. Keep only the stack-head identifier
in an external local variable. Pop a frame by loading its link and direction
BEFORE modifying or rotating the node. This is a linked stack inside zero
blocks whose memory is already counted.

Three details make this safe rather than merely suggestive:

A. JOIN(left,pivot,right). Descend the heavier tree's spine, placing one frame
   in each visited spine node. The detached pivot belongs to neither input
   tree, so it cannot overwrite a live frame. At the base, attach the pivot
   between balanced-height trees; unwind and rebalance using the saved links.
   Every frame owner is distinct. Rotations do not read or modify the scratch
   fields, and the next frame has already been saved before each rotation.

B. SPLIT(tree,key). Descend one search path, putting frames in its nodes.
   During unwinding, pop the current node before invoking JOIN on the relevant
   child trees and that node. A nested JOIN visits only the already-processed
   descendant trees and the untouched sibling subtree. No still-pending SPLIT
   frame owner is in those trees: pending owners are strict ancestors on the
   original search path. Therefore JOIN may safely reuse descendant scratch
   fields without corrupting the suspended SPLIT frames.

C. Deletion and insertion. Delete a key by two SPLITs and a JOIN without that
   key. Insert a detached node by one SPLIT and a JOIN with that node. Joining
   two trees without a pivot first pops a maximum node using another iterative
   spine traversal, then joins around that detached pivot. These calls are
   sequential or have fixed-depth nesting. They introduce no recursive stack.

All live traversal frames occupy actual tree-node blocks, which remain
logically zero throughout their use. Raw payload materialization happens only
after the tree operations have returned. The ordinary call graph of the
implemented operations has no cycle; its measured static depth is 11, a
constant independent of n. Each function has only a fixed number of scalar
locals and constant-size return values.

Thus the additional external workspace is O(1) words. Old frame contents
need not be erased: a later push initializes the fields it will read, and
status queries ignore both fields entirely.

7. GENERAL CORRECTNESS, TIME AND SPACE

Correctness theorem. Starting from an all-zero status vector, after every
finite sequence of PASS and interval WRITE operations, USE(i) returns true
exactly when a PASS(i) has occurred since the last interval WRITE containing i.

Proof. Initialization satisfies I1–I4 and decodes to all zeros. Section 3
shows that PASS preserves the invariant and changes exactly bit i to one.
Sections 4–5 show that WRITE preserves the invariant and changes exactly its
interval to zero. USE decodes the invariant by a predecessor test or a raw
bit read. The scratch-field argument shows that the iterative implementation
performs the same tree transformations without overwriting any live frame or
valid payload. Induction on the event sequence proves the claim. No event
count or unbounded label enters the representation.

Time theorem. All operations take O(1+log(z+1)) worst-case time, where z is
the number of maximal zero-block runs immediately before the operation;
global reset takes O(1). In particular the uniform bound is
O(1+log(1+n/w)).

Proof. An AVL tree with z nodes has height O(log(z+1)). JOIN has cost bounded
by the height difference plus one. SPLIT has logarithmic total cost: joins
on the unwinding path have telescoping height differences, not independent
logarithmic costs that multiply into log^2. Standard AVL insertion, deletion,
split and join give the stated bounds; a constant number occur per monitor
operation. The zero-run count increases by at most a constant during any one
event. Maintaining the embedded frames costs constant extra work per visited
node and does not change the asymptotics. At most two six-word blocks require
direct masking, and PASS materializes at most one. Since z<=q, the uniform
bound follows. See [BFS22], Theorem 7 and Table 2 for the split/join machinery.

Space theorem. Retained mutable storage is at most

                    6w*ceil(n/(6w)) + w < n+7w

bits, for the word array and one root word. All tree and frame fields are
already INSIDE those array words. Immutable size/address configuration and
policy are accounted separately. A fixed number of local words suffices
throughout an operation, so peak protected mutable storage is n+O(w).

The lower bound of n bits still applies: every subset of statuses is reachable
by issuing its PASS operations from the all-stale state and is distinguishable
by USE. Hence this construction is within additive O(w) bits of the information
minimum while supporting logarithmic worst-case operations. This does not mean
the additive constant, the number of extra bits, or the running time is optimal.

8. CONSEQUENCES FOR DEPENDENCY FAMILIES

If each object's invalidation set is a union of at most r disjoint intervals
in one supplied common order, implement a WRITE by r range clears. The bound
becomes O(1+r*(1+log(1+n/w))) for WRITE, with unchanged protected memory and
logarithmic PASS/USE. The interval list and ID ordering belong to static policy.

Laminar invalidation sets admit such an ordering with r=1, by a depth-first
ordering of the inclusion forest's singleton leaves. This applies to the
sets of CLAIMS invalidated by each object, not an unexamined transpose of the
dependency relation. No efficient algorithm for finding the minimum r over
all orders is claimed here.

The construction does not handle arbitrary overlapping sets in logarithmic
time automatically: their interval counts may be large. It therefore does
not conflict with the earlier multiphase or OMv lower bounds.

Compared with the earlier n+O(w)-bit blocked construction, this changes the
worst-case bound for PASS/WRITE from O(1+n/w^2) to logarithmic, while changing
USE from constant to logarithmic. It is a different point on the trade-off,
not domination in every operation. Compared with the earlier wide tree's
n+o(n) protected bits and O(log_w n) operations, it spends fewer extra bits
and has a larger time bound. A complete tight curve remains unproved.

9. A SMALL LOWER-BOUND CHECK, AND ITS LIMIT

For the full range-clear interface, start with every status fresh. Clearing
the n(n+1)/2 different nonempty intervals gives that many different logical
outputs, plus the unchanged output for an empty interval.

From a fixed representation in L w-bit mutable cells, at most
1+L*(2^w-1) distinct physical states can be reached by changing at most one
cell. Therefore one-cell range clearing for ALL intervals requires

                 L*(2^w-1) >= n(n+1)/2.

For w=ceil(log2(n+1)), this requires Omega(n) cells, or Omega(nw) allocated
bits. In particular n+O(w) bits cannot support every interval by changing
only one word at that exact word size. The argument counts cell changes,
not reads or arithmetic. It assumes the direct two-endpoint interface, not
a fixed family with only a small number of possible intervals.

This is an elementary branching-count obstruction. It rules out one word
change in that regime, not constant-time algorithms with two or more writes,
and certainly not all sublogarithmic algorithms. Increasing the word width
by a constant factor can make this particular inequality uninformative. It
does not prove that the logarithmic construction is time-optimal.

Targeted searches covered initializable arrays, subarray/range clearing,

before presenting it as an original contribution.

verify_inplace.py checks:
- exhaustive short histories against an independent backward-history oracle;
- multi-block histories, so tests exercise tree storage rather than just bits;
- every representative block-status vector through eight blocks, all block
  intervals, and renewal of the physical block that holds the root node;
- randomized partial intervals, unaligned endpoints, and final-block padding;
- fragmented trees, bulk deletion, repeated split/rejoin, ascending/descending
  updates, and dense boundary blocks;
- every tree's order, balance, height, disjoint/maximal zero intervals, node
  ownership, absence of cycles and agreement with the logical bit vector;
- initialization over arbitrary old word contents;
- the production method call graph, which contains no recursion.

The recorded run passed. verification.json contains the counts. These tests
are supporting evidence for the implementation, not a proof of asymptotic
time, an independent audit of all prior work, or a novelty determination.
Python object allocation is not the claimed physical bit count; the word-RAM
representation and constant-workspace argument are specified above.

The principal remaining questions are whether sublogarithmic worst-case
operations are possible at n+O(w) peak bits, which simultaneous time bounds
can be proved optimal, and how far beyond bounded interval representations
the same space bound extends. These are unresolved by this note; their exact
literature status is not asserted.

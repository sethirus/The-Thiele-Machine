Pipeline (all under coq/kami_hw, generated by scripts/generate_*.py):
RuleNext.v (hwb_after, hwb_after_union) -> RuleStep.v (rule_next_correct, step_next) -> StepEval.v (hw_field tactic, step_keeps_*) -> StepFields.v (per-opcode field equations) -> StepRefineCommon.v + PopcountSWAR.v -> StepRefine.v (step_<op>_refines against kami_step).

**Why:** direct vm_compute/cbn of the step rule is too slow; lazy with word ops and all 138 hw_* projections blacklisted, then clear_concrete_word_casts, then split innermost stuck conditions, proves each field in ~0.05 s.

**How to apply:** Traps found: f_equal on the 30-field snapshot hangs (use kami_snapshot_ext); `destruct` sees different implicit word sizes (RegIdxSz vs 4, MemAddrSz vs 7) so unfold those first; numerals >5000 are opaque Nat.of_num_uint to lia; `unfold WordSz` also changes implicit args of #x, use `change (pow2 WordSz) with (pow2 32)`; regenerating a file bumps timestamps and triggers long rebuilds; a Qed that converts `attrType dispatch_rule type` can hang, isolate that conversion in a tiny lemma. Related: [[c2-cpu-matches-vm-decision]], [[guarded-coq-builds]].

Morph family (2026-09-14 night): generate_step_fields_morph.py -> StepFieldsMorph.v, generate_step_refine_morph.py -> StepRefineMorph.v (separate files so StepFields/StepRefine stay byte-identical). Extended words use hw_field_rich (decides closed wlt_dec first). More traps: `first [...]` hides a stack overflow as "No applicable tactic" (never `cbn; lia` on pow2 32); a full stop inside a generated `all:` tactic string ends the sentence so later tactics hit only goal 1; `inline()` rewrites any bare A/C/E identifier, so don't name hypotheses A; `rewrite` of a rich-state pair equation overflowed, `pattern l; refine (eq_rect_r _ _ H)` works; implicit widths: use `apply`/specialised lemmas stated at WordSz. Debug helper: ~/.cache/thiele-guard/showleft.sh IN OUT turns the last closer line into try+Show.

CHSH_LASSERT / FSM work (2026-09-14 night): the CHSH FSM rule body could not be reduced at a symbolic boundary (cbn over the rule OOM; lazy unfolds the whole module); fixed by factoring the CPU rule into reads + `chsh_fsm_decoded` (generate_chsh_decoded.py mirrors BoundaryDecoded). RuleEnabled.v: write-distinctness must be a computed `if`, not `/\` (conj proof terms grow quadratically); rewriting inside an unfolded rule hangs, use head unification (`attrType r type = ReadReg n k (fun x => Assert_ ...)` by reflexivity). Arithmetic: never let unification see `pow2 N` against a different form (eassumption, naming `pow2 768` when the term says `pow2 (384+384)`): pass bounds with explicit `exact`. CHSH_LASSERT closed 2026-09-14/15 (ChshArith, ChshDecoded, ChshStepFields, ChshFsm, ChshPhases, ChshRun, ChshRetire; generators generate_chsh_*.py). Key technique for FSM rules: mirror each LET as `evalExpr` of the same Kami expression (generate_chsh_fsm.py parses the CPU text), prove field equations with `exact_no_check (eq_refl x)` so the KERNEL does the conversion at Qed (tactic reflexivity took 367 s vs 0.03 s kernel); before a kernel check that must resolve a phase mux, decide closed `weq` with vm_compute + change (100 s -> 0.3 s). A wrong statement under exact_no_check only fails at Qed, reported inside the surrounding rewrite's eq_ind_r. Next FSMs (LASSERT, morph/coupling) should reuse this pipeline; LASSERT FSM rule body may need the same CPU factoring (reads + decoded definition).

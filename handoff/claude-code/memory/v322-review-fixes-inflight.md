**As of 2026-09-16 later: C1/C2 gate is CLOSED. 90% (9/10 delivery gates). Only Gate E remains open.** The prior session (same day, earlier) closed the ten guard-class opcodes' outside-domain relation across all six ISA-v2 encodings (`OutsideDomain.v` + `OutsideDomainMaster.v`) and correctly identified `DispatchLets.dd_rich_fault` -- a fifth, separate guard (ISA-version/format validity, inline malformation, descriptor-range faults, table overflow, cert-descriptor validity) -- as the one remaining piece blocking C1/C2 closure. This session closed it.

**Key finding that made it fast:** `dd_rich_fault`'s six disjuncts turned out to be almost entirely closed constants, not a per-opcode case analysis. Every one of `RetireMaster.admitted`'s 55 constructors fetches either `legacy_word` (format `FMT_LEGACY`, flags 0) or `StepFieldsMorph.rich_word` at a fixed format literal (3 = `FMT_MORPH_INLINE` or 5 = `FMT_CERT_INLINE`, flags fixed to 4). Neither shape ever uses `FMT_DESC`, so two of the six disjuncts (`dd_generic_desc_range_fault`, `dd_cert_desc_invalid`, both gated on `format_id == FMT_DESC`) are false unconditionally, for any opcode, no premise needed. ISA-version and inline-malformation similarly collapse to closed constants once format/flags are fixed. The **only** live-state-dependent disjunct is table overflow (`dd_rich_table_overflow`), and only for the three morph-allocating opcodes (MORPH, COMPOSE, MORPH_ID) -- and exactly the six constructors that need it already carry the `hw_morph_next_id`/`hw_coupling_desc_next_id` room-bound premises (verified by mechanically extracting every constructor's premise list from `RetireMaster.v` via a Python script and checking presence/absence against the math). **Zero new admission premises were needed anywhere.**

**New files** (registered in `_CoqProject`, all Qed, zero admits):
- `kami_hw/RichFaultWords.v`: bridges `StepFieldsMorph.rich_word` (fixed flags=4 encoding) to `RichWordDecode.rich_word` (the general six-encoding word `OutsideDomainMaster.v` already uses), transferring its `rw_*_correct` decode lemmas.
- `kami_hw/RichFaultMaster.v`: `dd_rich_fault_unfold` + one falsity lemma per leaf + three top-level theorems, each fully general over every opcode of its word-shape (not a 55-way enumeration): `dd_rich_fault_false_legacy`, `dd_rich_fault_false_morph_inline`, `dd_rich_fault_false_cert_inline`.
- `kami_hw/RichFaultRetireMaster.v` (Python-generated from `RetireMaster.v`'s own `admitted` inductive, verbatim extraction to avoid hand-transposing bit-variable lists): one corollary per admitted constructor.

**Two generator bugs hit and fixed, worth remembering for future codegen against this file family:** (1) don't derive a lemma's `forall`/`intros` binder list from a word-constructor call's argument tokens directly -- some constructors (e.g. `adm_pdiscover`) pass literal `false` for some operand bits, not a bound variable, so the binder list must come from the constructor's own `forall` header with literal tokens filtered out. (2) a generated "walk to the Nth disjunct of an N-way `\/` via `right;right;...;left;reflexivity`" combinator must still append `reflexivity` on the *last* disjunct (no trailing `left` needed, but the equality goal still needs closing) -- a bare `right;` chain with nothing after it leaves an unfinished bullet.

**Proof-technique traps for this `dd_*` file family** (Kami-generated accessors reference each other as opaque `Var` values, not by re-inlining the expression tree): (a) a decode-fact rewrite only reaches a read site if every intermediate `dd_*` accessor between them is in the `unfold` list -- missing one leaves a `dd_flags`-shaped term buried a level deep, and `vm_compute` then tries to reduce through the *symbolic* `combine` word structure directly (the classic trap from [[coq-implicit-arg-destruct-gotcha]]'s family) instead of hitting the now-concrete value, exploding to a multi-GB guard kill. (b) when the same Kami subexpression appears twice (once directly, once via an opaque named accessor like `dd_morph_alloc_opcode`), a single `destruct` only resolves *both* occurrences if the accessor is unfolded *before* the destruct, so both copies are the literal same post-`cbn` term. (c) a custom `Ltac name := cbn [...].` cannot take a trailing `in H` the way built-in `cbn`/`cbv` can -- write the reduction out at the hypothesis site directly.

# Emitted-prefix invariant source review

Source review: NormalizationPrefix.v against NormalizationLoop.v and the actual normalization_emit_updates equations. This is an independent source inspection of delegated work within the same environment, not external reproduction.

The invariant relates the compacted table slice [base,out) to candidates already processed in [base,i), selected according to whether they recur anywhere later in the immutable original range. It separately retains equality with the original tables on [i,end), and bounds base<=out<=i<=end<=16. Using the full original endpoint in selection is necessary: normalizing only the processed prefix would incorrectly retain an occurrence repeated in the unprocessed suffix.

Establishment uses an empty selected prefix and unchanged tables. Preservation uses i<end to derive out<16, exclude truncated-index aliases, preserve previously emitted cells, and preserve the unread suffix. The current candidate and every comparison in its remaining suffix agree with the raw tables, so the scanner's duplicate decision equals the raw-list decision. In the keep case, the actual emit writes the current candidate at out and extends the selected prefix. In the duplicate case, both table and output prefix remain unchanged. The actual-map theorem connects these table functions to the source/destination register lookups of normalization_emit_updates.

At i=end, the selected prefix covers the original admitted slice. The terminal theorem derives exact ordered equality with Coq nodup; it does not assume a set-only equality. Candidate and output register lemmas match the real update maps. The end pointer is replaced by the compacted output pointer on the last candidate; the invariant's immutable original end must remain a proof parameter, not be confused with that overwritten hardware field.

No concrete mismatch was found. The invariant deliberately does not yet describe the scan phase, partial duplicate accumulator, or every control register. Those facts must be combined with actual Step/Multistep execution in the outer loop proof. It also does not prove dispatch reachability, descriptor freshness, previously allocated-region preservation across all earlier phases, or global retirement/fault behavior. The no-wrap interpretation uses the stated bounds, not unrestricted natural equality for hardware words.
